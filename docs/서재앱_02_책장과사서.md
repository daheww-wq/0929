**서재앱 02 책장과사서**

이 문서가 답하는 질문: 서재가 어떤 규칙으로 정리되고, 사서가 언제 무엇을 판단하고 말하나
현재 기준 문서. 결정이 바뀌면 이 자리에서 고친다. 바뀐 이력은 `서재앱_00_허브.md` 결정 로그에 남긴다.
버전 구분(MVP / 다음 / 그다음)은 `서재앱_03_기능과흐름.md`에만 적는다. 화면에서 어떻게 보이는지는 04, 뒤에서 어떻게 도는지는 05.
검토안 비교와 발산 과정은 기록 문서 `서재앱_책장구조_260922.md`에 남아 있다.

말의 주체: 이 문서에서 "나"는 서재앱을 쓰는 사용자(다혜)다. "사서"는 앱 안에서 분류하고 말을 거는 LLM이다.

**0. 결정 요약**

1. 칸 축: 주제로만 칸을 나누고, 유형·분량·오래 안 연 정도는 책 모양(시각 기호)으로 표시. 출처·시기는 가리키면 뜨는 라벨. 관점은 태그로 달아 칸 안 배열에만 사용. 보기 전환은 필터 수준("이 칸에서 논문만 보기")
2. 여러 칸에 걸치는 책: 참조 카드. 진짜 책은 한 칸에만, 관련 칸에는 반투명 책·색인 카드. 한 책에 최대 2개
3. 첫 칸 생성과 신간 처리: 기존 북마크를 가져오면 들어온 책을 보고 사서가 칸을 제안하고, 가져오지 않으면 관심 주제로 넓은 칸 3~5개에서 시작. 신간은 확실하면 해당 칸에 신간 띠지를 두르고 꽂고, 애매하면 임시서가로
4. 계층 깊이: 2단(책장 → 칸)으로 시작. 책장이 많아지면 사서가 방으로 묶기를 제안 (기준은 보류, 12절)
5. 관리 권한: 평소엔 사서가 정리하고, 사용자가 수정 버튼으로 손대는 순간 그 자리에서 권한이 넘어옴. 사서가 관리하는 칸은 인쇄 라벨, 내가 관리하는 칸은 손글씨 이름표
6. 책 표시: 책등 색 = 유형, 두께 = 분량(유형별 기준), 빛바램 = 마지막으로 펼친 뒤 지난 시간, 신간 띠지, 포스트잇 = 내 메모·하이라이트
7. 칸 안 배열: 담은 순서가 기본 (새 책이 오른쪽 끝). 정렬 바꾸기와 유형 필터 제공
8. 트리거 수치: 12절 표. 초기값이며 바꿀 때마다 정책 버전으로 기록
9. 전시 서가: 주제 칸과 별도로 책장 맨 앞 진열대. 사서가 2주마다 꾸리고, 사용자가 직접 만들 수도 있음
10. 정답지: 사서가 분류한 책 중 사서가 칸마다 고르게 뽑은 20권을 나(사용자)가 채점한 결과. 규칙을 바꿀 때마다 회귀 확인에 쓴다 (5절)
11. 사서가 말을 거는 상한: 대답이 필요한 질문만 하루 2개. 보고·상태 표현은 상한 밖 (7절)

표기 원칙 (결정 5·9 공통): 사서가 만든 것은 인쇄 라벨, 내가 만든 것은 손글씨. 칸 이름표와 전시 제목 모두 같은 규칙. 별도 기호를 얹지 않고 글씨체만으로 구분되어 책장이 덜 복잡하다

기능 이름 규칙: 도서관 용어로 통일한다. 신간(띠지), 임시서가, 전시 서가, 진열대, 들어오는 글, 상호대차, 보존 서고, 참조 카드, 정답지, 수서, 장서 점검. 새 기능이 생기면 "도서관에서 이걸 뭐라고 부르지?"가 이름 짓는 기준이 된다. 분류에서 쓰는 통제 어휘 원리를 기능 이름에 적용한 것이다

화면에 나오는 말: 기능 이름은 도서관 용어로 짓되, 사용자가 처음 보고 뜻을 모를 말은 화면에서 쉬운 말로 쓴다. 칸마다 적는 기준은 도서관에서 범위주기라고 부르지만, 화면과 문서 모두 "이 칸에 들어오는 글"(줄여서 들어오는 글)로 부른다

디자인 원칙: 무조건 시각적으로 예쁘게, 세련되게. 책 모양 시안은 넓은 화면(새 탭) 기준으로 디자인 단계에서 그린다

기획과 디자인의 구분: "이게 바뀌면 동작·규칙·데이터가 바뀌는가?" 바뀌면 기획, 보이는 방식과 느낌만 바뀌면 디자인. 책 모양에 어떤 정보를 어떤 우선순위로 담을지는 기획, 색 팔레트·비율·표현 방식은 디자인

**1. 칸과 통제 어휘**

칸마다 붙이는 정보
- 우선어: 칸 이름 하나로 통일 ("LLM 평가")
- 별칭(UF): LLM-as-a-Judge, 자동 평가, judge 모델 → 전부 이 칸으로
- 들어오는 글: "여기 들어오는 것 / 다른 칸으로 가는 것". 화면에는 "이 칸에 들어오는 글"로 보인다. 도서관 분류표의 범위주기(scope note), 포함·제외 주기와 같은 역할
- 상위·하위·관련 칸(BT/NT/RT): 칸 사이 관계. 참조 카드와 추천의 재료

들어오는 글이 곧 사서가 배운 기준이다
- 칸마다 `{포함: [문장들], 제외: [{조건, 보낼 칸}]}` 형태로 저장하고, 분류 프롬프트에 그대로 들어간다
- 자기개선 루프의 수정 단위도 칸별 들어오는 글이다. 프롬프트 전체 대신 옮긴 기록이 쌓인 칸의 들어오는 글만 사서가 수정안을 내고 사용자가 승인한다. 수정 범위가 작아 검증이 쉽고, 버전 관리도 칸 단위로 된다
- 사용자는 칸 설정에서 들어오는 글을 직접 읽고 고칠 수 있다
- 수서(외부 자료 추천)도 이 들어오는 글을 검색 기준으로 쓴다 (01 4-5)

칸 축 결정 상세 (결정 1)
- 사서(LLM)가 판단하는 건 주제 하나로 줄어 확률적 판단이 한 종류가 된다
- 유형·출처·시기는 담을 때 뽑는 메타데이터라 코드로 검증된다(결정론적). 판단 주체가 깔끔하게 나뉜다
- 관점(방법론, 사례, 비판·반론, 서베이)은 태그로 흡수해 칸 안 배열에만 쓴다
- 유형별·질문별로 다시 늘어놓는 보기는 필터 수준으로만 둔다

**2. 첫 칸과 신간 처리 (결정 3)**

1. 온보딩에서 기존 북마크 가져오기를 고르면, 관심 주제를 묻지 않는다. 수집하는 동안 책은 임시서가에 모이고, 끝나면 사서가 들어온 책을 보고 칸 초안(칸 이름과 들어오는 글 한 줄씩)을 제안한다. 내가 고치고 확정하면 책이 칸으로 꽂힌다. 실제 자료를 보고 분류를 만드는 문헌적 보증 원리와 같다
2. 가져오기를 건너뛰면 관심 주제를 적고, 사서가 그걸로 넓은 칸 3~5개 초안을 만든다. 칸 이름과 들어오는 글 한 줄씩. 내가 고치고 확정한다
3. 관심 주제도 건너뛰면 칸 없이 시작하고, 담은 책이 임시서가에 모인다. 같은 무리가 3권 모이면 사서가 칸을 제안한다 (아래에서 위로 만들어지는 길)
4. 신간은 확실도에 따라 두 갈래

| 경우 | 가는 곳 | 보이는 모습 |
|---|---|---|
| 확실히 구분됨 | 바로 해당 칸으로 | 신간 띠지를 두른 채 꽂힘 |
| 애매함 / 맞는 칸 없음 | 임시서가 | 사서가 붙인 칸 이름 후보와 함께 대기 |

- "확실함" 기준: 3번 분류해서 3번 모두 같은 칸이 나오고, 그 칸의 들어오는 글과도 맞을 때
- 임시서가에 같은 무리가 3권 모이면 새 칸 제안, 오래 혼자 남은 책은 가까운 칸으로 옮기자고 제안
- 그 뒤로는 칸이 두꺼워질 때마다 분할 제안
- 신간 띠지: 펼쳐보면 벗겨진다. 띠지 두른 책 = 안 읽은 새 책. 칸별 띠지 수로 요즘 많이 담는 주제가 보인다
- 크롬 북마크 폴더는 서재의 칸과 별개다. 폴더는 책을 가져오는 단위로만 쓰고, 분류 기준으로 쓰지 않는다. 크롬 북마크 구조는 건드리지 않는다
- 후보: 기존 북마크 폴더 이름을 사서가 첫 칸 초안을 만들 때 참고 자료로 쓰기

---

**3. 경계 책: 참조 카드 (결정 2)**

- 진짜 책은 한 칸에만, 관련 칸에는 반투명 책·색인 카드("→ LLM 평가 칸에 있음"). 도서관의 "see also"와 같은 원리
- 칸 두께는 진짜 책만 센다. 반투명 책으로 "다른 칸에도 걸친 책"과 칸 사이 연결이 보인다
- 3회 분류 결과가 흔들리면 가장 많이 나온 칸에 진짜 책, 두 번째 칸에 참조 카드. 확률적 실패를 버리지 않고 정보로 쓴다
- 1등 칸도 확실하지 않으면 임시서가로
- 한 책에 참조 카드 최대 2개
- 참조 카드에서 진짜 책을 그 칸으로 옮기는 버튼 제공. 옮기면 분류 라벨로 기록
- 참조 카드를 눌러 책을 열었는지 기록 → 칸 관계(관련 칸)와 추천의 재료
- 참조 카드는 규칙이 바뀌거나 책이 옮겨질 때 다시 계산해서 따라간다

---

**4. 실패 유형별 처리 경로**

| 구분 | 감지 방법 | 사서의 행동 |
|---|---|---|
| 결정론적 (매번 같은 칸으로 잘못 감) | 같은 칸 A→B 이동이 비슷한 책에서 3번 반복, 재분류해도 같은 결과 | 규칙을 묻는 질문 → 확인 → 들어오는 글 수정 |
| 확률적 (돌릴 때마다 다른 칸) | 3회 분류 결과가 흔들림 | 규칙 질문 없이 참조 카드·임시서가로 |

- 규칙 질문은 결정론적 실패에만 던진다. 확률적 실패에 규칙 질문을 던지면 규칙이 계속 늘어나 들어오는 글이 누더기가 된다

**5. 정답지**

뜻: 사서가 규칙(들어오는 글)으로 분류한 책 중 20권을 사서가 골라 올리고, 나(사용자)가 채점한 결과. "이 책은 이 칸이 맞다"는 책과 칸의 짝 목록이다. 평가 일의 골든셋과 같다

무엇이 정답이 아닌가
- 크롬 북마크 폴더: 예전에 내가 만든 다른 체계라 정답이 아니다. "읽을거리"처럼 주제가 아닌 폴더도 있다
- 규칙: 사서가 만든 것이라 시험을 받는 쪽이다. 규칙이 정답이면 규칙을 검사할 방법이 없다

순서
1. 칸을 만든다 (사서 초안 → 내가 확정)
2. 책이 들어온다 (새 북마크, 또는 고른 북마크 폴더 가져오기)
3. 사서가 규칙으로 분류한다 = 사서의 답
4. 사서가 칸마다 고르게 20권을 뽑아 확인 카드로 올리고, 나(사용자)가 "여기 맞아요 / 옮기기"로 채점한다 = 정답지
5. 이후 규칙이 바뀔 때마다 사서가 새 규칙으로 정답지 20권을 다시 분류해 스스로를 채점한다

뽑는 방법
- 분류가 끝난 뒤 칸마다 고르게 뽑는다. 칸 크기 비율대로 뽑되, 칸마다 최소 2권, 임시서가에서도 2권
- 예: 가져온 88권이 LLM 평가 25, 에이전트 20, UX 18, 프로덕트 12, 트렌드 5, 임시서가 8로 나뉘면 → LLM 평가 5, 에이전트 4, UX 4, 프로덕트 3, 트렌드 2, 임시서가 2권
- 선착순으로 뽑지 않는 이유: 한 폴더에서 먼저 들어온 20권은 한두 칸에 몰린다. 그러면 다른 칸의 규칙을 바꿀 때 회귀 확인이 아무것도 지켜주지 못한다
- 뽑는 시점: 가져오기가 끝났을 때, 또는 서재에 책이 40권 모였을 때 중 먼저 오는 때 (초기값)

확인 방식
- 사서가 20권을 한 장의 확인 카드로 새 탭 사서 자리에 올린다. 책마다 "여기 맞아요 / 옮기기"
- 담는 순간 뜨는 화면이 없으므로(북마크로 담기) 확인은 새 탭에 쌓인다
- 며칠 지나도록 확인하지 않으면 사서 판단대로 둔다
- 들어오는 글은 첫 확인 카드에서 한 줄로 보여준다 ("이 책은 'LLM 평가' 칸에 꽂았어요. 이 칸에는 평가 기준과 자동 평가를 다루는 글이 들어와요"). 처음부터 설명을 읽는 대신 첫 확인에서 기준을 알게 된다
- 정답지 확정 뒤에 들어오는 책은 확인 없이 조용히 꽂힌다

쓰임
- 규칙 질문의 회귀 확인 (6절)
- 첫 제안 수락률 = 사서 성능의 출발점 수치
- 포트폴리오에서 "별도 라벨링 없이 회귀 테스트 세트가 생기는 구조"

정답지가 생기기 전
- 책을 옮긴 기록은 쌓지만 규칙 질문은 띄우지 않는다. 회귀 확인의 기준이 없기 때문이다

정답지 유지
- 칸이 11개 이상이라 칸당 2권이 안 되면 칸당 1권으로 줄이고 20권은 유지한다
- 정답지에 든 책을 옮기면 사서가 "처음 확인하신 칸과 다른데 옮길까요"를 묻는다. 사용자에게 정답지라는 말은 꺼내지 않는다. 옮기면 새 칸이 정답이 되고 내 기준이 바뀐 것으로 기록한다. 취소하면 원래 칸으로 돌아간다. 편집 중이라 하루 질문 상한 밖
- 정답지를 만든 뒤 새 칸이 생기면, 그 칸에 책이 3권 모였을 때 2권을 작은 확인 카드로 정답지에 추가한다. 새 칸만 회귀 확인에서 빠지는 것을 막는다
- 칸을 나누거나 합치거나 지우면 정답지의 정답도 확정한 배치대로 따라간다

**6. 규칙 반영 로직 ("앞으로도")**

흐름
1. 책을 끌어서 다른 칸으로 옮긴다. 옮긴 기록만 남고 사서는 조용하다
2. 같은 방향 이동이 3번째가 되면, 다음에 새 탭을 열 때 사서 자리에 질문 카드가 놓인다
3. 질문 예: "최근 'LLM 평가'에 꽂힌 책 3권을 '에이전트' 칸으로 옮기셨어요. 에이전트를 평가하는 글은 앞으로 '에이전트' 칸에 둘까요?"
4. 선택지: 앞으로도 이렇게 / 이번 책들만 / 새 칸 만들기 ('에이전트 평가'). 선택지마다 영향받는 책 목록을 함께 보여준다
5. "앞으로도"를 고르면 들어오는 글 변경 전후를 한 줄씩 보여주고, 영향 미리보기와 정답지 회귀 결과를 함께 보여준다
6. 승인 → 반영, 들어오는 글 버전 저장, 되돌리기

저장하는 것

| 저장하는 것 | 내용 |
|---|---|
| 이동 기록 | 책 id, 이전 칸, 새 칸, 시각, 그때의 분류 근거 |
| 들어오는 글 | 칸마다 `{포함: [문장들], 제외: [{조건, 보낼 칸}]}`. 분류 프롬프트에 그대로 들어감 |
| 들어오는 글 버전 | 버전 번호, 변경 전후, 근거가 된 이동 기록 id, 적용 시각 |
| 재질문 금지 목록 | (이전 칸, 새 칸, 특징) 조합. "이번 책들만"을 고른 것이 들어감 |

단계별 처리
1. 질문이 뜨는 조건 (코드): 정답지가 확정되어 있고, 최근 30일 안에 같은 (이전 칸 → 새 칸) 이동이 3건 쌓이고, 그 조합이 재질문 금지 목록에 없을 때. 조건이 맞으면 질문 카드를 대기열에 넣고 새 탭에서 하루 2개까지 표시
2. 규칙 후보 만들기 (LLM, 형식 고정)
   - 입력: 옮긴 책 3권의 제목·요약·원래 분류 근거 + 두 칸의 현재 들어오는 글
   - 출력 형식: `{ "특징": "에이전트를 평가하는 글", "이전 칸 제외 추가": "에이전트 평가를 다루면 → 에이전트", "새 칸 포함 추가": "에이전트의 성능·품질 평가" }`
   - 코드 확인: 형식이 맞는지, 건드리는 칸이 그 두 개뿐인지, 기존 문장과 겹치지 않는지. 어긋나면 질문을 띄우지 않고 다시 생성
3. 영향 미리보기 (코드 + LLM, 비용 상한)
   - 후보 고르기: 이전 칸의 책 중 그 특징에 가까운 순으로 최대 20권 (임베딩이 없을 때는 키워드와 제목으로)
   - 새 들어오는 글로 그 20권을 다시 분류 (LLM 호출 20회 상한)
   - 칸이 바뀌는 책만 목록으로 표시: "기존 책 5권도 옮겨져요" + 제목
   - 정답지 20권도 다시 분류해 함께 표시: "정답지 20권 중 19권은 그대로예요". 유지율이 떨어지면 경고 (회귀 확인)
4. 승인 후 (코드): 들어오는 글 새 버전 저장 → 미리보기에서 바뀐 책 실제 이동 → 참조 카드 재계산 → 되돌리기 배너
5. 되돌리기: 버전을 되돌리면 들어오는 글이 이전 버전으로 돌아가고, 그때 함께 옮긴 책들도 원래 칸으로. 이동 기록에 "이 버전으로 옮겨진 책"이 남아 있어 역으로 실행된다. 직후에는 배너, 그 뒤에는 버전 목록에서
6. 다른 선택지
   - 이번 책들만: 그 책들에 "이 자리 고정" 표시, (이전 칸, 새 칸, 특징)을 재질문 금지 목록에 추가. 규칙화하지 않겠다는 판단이라 같은 질문을 반복하지 않는 근거가 된다
   - 새 칸 만들기: 칸을 만들고 들어오는 글 초안을 받은 뒤 같은 미리보기 단계를 거친다

비용: 질문 한 번에 LLM 호출 최대 41회(규칙 후보 1 + 미리보기 20 + 정답지 20). 하루 질문 상한 2개라 하루 82회가 최대. 정답지 재분류 결과는 버전마다 저장해 같은 버전을 다시 계산하지 않는다

자기개선 루프와의 관계
- 지금은 신호를 쌓고, 수정은 사서 질문으로 사람이 직접 승인한다
- 루프를 돌릴 재료가 쌓인 뒤에 자동화한다: 실패 사례 모아 원인 진단 → 들어오는 글 수정안 자동 생성 → 정답지로 회귀 확인 → 승인 후 반영·되돌리기
- 루프의 최소 구조: 기록(입력·중간 단계·출력 전부 저장) → 평가(코드 체크 + LLM judge, 점수와 실패 이유를 자연어로) → 반성(실패 사례를 묶어 원인 진단과 수정안 요청) → 검증(별도 검증 세트로 회귀) → 반영(승인 후 교체, 버전 관리, 나빠지면 되돌리기) → 사람 점검(주기적으로 출력을 직접 보고 기준 갱신). DSPy의 GEPA 옵티마이저로 반성·검증 단계를 가져다 쓸 수 있다
- 함정: judge가 좋아하는 방향으로만 바뀌는 문제(judge를 사람 판단에 먼저 맞춤), 평가 세트에만 맞춰지는 문제(개선용과 검증용 사례 분리), 프롬프트로 안 고쳐지는 실패(수집 실패·도구 호출 깨짐은 구조 문제로 따로 처리)
- 사람이 루프에서 빠지지 않는다. 자동 루프는 정해진 기준 안의 최적화는 잘하지만 기준 자체는 바꾸지 못한다. criteria drift는 사람 몫

**7. 사서**

캐릭터
- 집사 고양이. 사람 일러스트는 호불호가 크고 표정 컷을 여러 장 그려야 해서 접었다
- 파츠 조합으로 상태를 만든다: 귀(평소/쫑긋/눕힘), 눈(뜸/반달/감음/곁눈질), 꼬리(말림/살랑/곧게), 손(빈손/책/돋보기/리본). 그림을 여러 장 그리지 않아도 상태가 다 나온다
- 그래픽 예산은 사서에 몰고, 책장과 목록은 단순한 도형과 글자로 간다. 책장과 종이는 차분하게, 사서와 이펙트만 카툰풍으로 대비

사서가 하는 일
- 담긴 책 분류, 신간 띠지, 임시서가 배치
- 들어온 책을 보고 칸 초안 제안 (가져오기 뒤)
- 정답지 확인 카드
- 규칙 질문, 칸 분할·병합 제안, 임시서가 → 새 칸 제안, 방으로 묶기 제안
- 북마크 가져오기 제안, 수집 결과 보고, 실패 보고
- 전시 서가, 저녁 큐레이션, 수서

새 탭을 열 때마다 사서가 무언가 하고 있다 (상태 표현)
- 아침: "어제 담은 세 권 정리해뒀어요"
- 수집 중: 책을 안고 선반으로 걸어가는 중
- 물어볼 게 있을 때: 고개를 들고 말풍선
- 실패가 있을 때: 귀를 눕히고 "두 건은 못 가져왔어요"
- 아무 일 없을 때: 선반 위에서 꼬리만 살랑이며 졸기
- 저녁: 램프를 켜고 "오늘 이 책은 어떠세요"

말 거는 규칙
- 조용한 상태가 기본이다. 기다리는 동안 실제로 움직인다. 결과를 보고한다. 내가 고치면 반응한다. 시간을 안다
- 기다리는 동안 하는 말은 재미있게 쓰되 실제로 하고 있는 단계와 맞춘다("책을 받아오는 중", "어느 칸이 어울릴지 고민하는 중"). 숫자 진행률을 같이 보여준다. 초안은 04 4절
- 하루 2개 상한은 대답이 필요한 질문에만 건다: 규칙 질문, 칸 분할·병합 제안, 임시서가 → 새 칸 제안, 방으로 묶기 제안, 북마크 가져오기 제안
- 상한 밖: 인사, 수집·실패 보고, 상태 표현, 정답지 확인(한 장에 묶음), 내가 고친 직후의 질문(편집 중이라 맥락이 살아 있음)
- 한 번에 1~2개씩 모아서 보여준다
- 읽는 중에는 묻지 않는다. 질문은 새 탭 사서 자리에 쌓인다
- 큐레이션·질문·전시 제목을 같은 사서 목소리로 전한다
- 출근길에 무시한 확인도 사서 자리에 남는다

관리 권한 (결정 5)
1. 기본: 책 배치와 칸 관리는 사서가 한다. 새 칸 만들기·분할처럼 구조가 바뀔 때만 제안한다
2. 수정: 책장·칸·책 어디서든 수정 버튼으로 직접 바꾼다
3. 바꾼 직후 사서가 한 번 묻는다: "이번만 바꿀게요" / "앞으로도 이런 책은 이렇게"(들어오는 글 수정) / "이 칸은 앞으로 제가 직접 관리할게요"(권한 이전)
4. 직접 관리하는 칸은 손글씨 이름표로 바뀐다. 사서는 그 칸 구조를 건드리지 않고, 두꺼워지면 분할 제안만 한다
- 표시 검토: 자물쇠는 잠겨서 닫힌 느낌이라 제외. 압정/핀, 리본·책갈피 대신 손글씨 이름표 채택
- 모든 수정마다 묻지는 않는다

| 수정 | 사서의 반응 |
|---|---|
| 책 한 권 옮기기 | 묻지 않고 기록만. 같은 방향 이동이 반복되면 규칙 질문 (6절) |
| 칸 이름 바꾸기, 칸 나누기·합치기 | 바로 질문 |
| 책장 수준 변경 | 바로 질문 |

칸 삭제: "이 책들을 어디로 보낼까요?"를 묻고, 임시서가 또는 내가 지정한 칸으로 보낸다

분할 제안 (모든 칸 공통, 손글씨 이름표 칸 포함)
- 트리거: 12절 표
- 제안에 담을 것: 새 칸 이름 2개, 각 칸 들어오는 글 초안, 책 배치안, "나중에" 버튼
- 사서가 관리하는 칸: 승인하면 사서가 제안대로 반영
- 손글씨 이름표 칸: 사용자가 칸 이름·책 배치를 고쳐서 확정
- 거절 시 2주 동안 같은 칸 제안 보류

**8. 책 표시 (결정 6)**

| 대상 | 표시 | 뜻 | 값 구간 | 데이터 출처 | 시작 시점 |
|---|---|---|---|---|---|
| 책 | 책등 색 | 유형 | 논문 / 기사 / 리포트·기타 (3색) | 메타데이터 (코드) | 첫날 |
| 책 | 두께 | 분량 (유형별 기준) | 짧음 / 보통 / 김. 기사는 글자 수, 논문은 페이지 수로 각각 나누고, 구간 값은 처음 담은 15권의 분포를 보고 정함 | 본문 글자 수·페이지 수 (코드) | 15권 뒤, 바뀌는 순간을 보여주며 |
| 책 | 빛바램 | 마지막으로 펼친 뒤 지난 시간 | 없음(7일 미만) / 7일 / 14일 / 한 달 / 세 달 / 반년 이상 | 열람 로그 (코드) | 첫날 |
| 책 | 신간 띠지 | 아직 안 펼친 새 책 | 있음 / 없음 | 열람 로그 (코드) | 첫날 |
| 책 | 포스트잇 | 내 메모·하이라이트 | 1~3개 (메모 수에 따라 늘고 3개에서 멈춤). 튀어나오는 위치 = 하이라이트한 본문 위치 | 메모·하이라이트 기록 | 첫날 |
| 책 | 반투명 | 참조 카드 (진짜 책은 다른 칸에) | 있음 / 없음 | 분류 결과 (LLM) | 첫날 |
| 책 | 반짝임 | 방금 들어온 책 | 있음 / 없음. 본 뒤 사라지고, 며칠 지나면 반짝임만 사라짐 | 담기 기록 (코드) | 첫날 |
| 칸 | 손글씨 이름표 / 인쇄 라벨 | 내가 관리하는 칸 / 사서가 관리하는 칸 | 둘 중 하나 | 사용자 수정 기록 | 첫날 |
| 칸 | 점선 칸 | 임시서가 | 있음 / 없음 | 분류 결과 | 첫날 |
| 칸 | 은은한 빛 | 새로 꽂힌 책이 있는 칸 | 있음 / 없음, 여러 권이면 칸마다 개수 | 담기 기록 (코드) | 첫날 |
| 전시 | 손글씨 제목 / 인쇄 제목 | 내가 꾸민 전시 / 사서가 꾸민 전시 | 둘 중 하나 | 전시 생성 주체 | 첫 전시부터 |

눈에 들어오는 순서 (우선순위): 1. 신간 띠지 → 2. 빛바램 → 3. 책등 색 → 4. 두께

설계 메모
- 분량: 시간 하나로 자르면 기사는 전부 "짧음", 논문은 전부 "김"이 되어 두께가 유형을 한 번 더 보여주게 된다. 그래서 유형별 기준을 쓴다. 내 서재 안 상대 비교는 책이 늘면 같은 책 두께가 저절로 바뀌어 제외, 두께 = 내 흔적은 포스트잇으로 흡수
- 두께 적용 시점: 처음 15권은 모든 책을 같은 두께로 두고, 15권이 모이는 날 "이제 책 두께로 분량을 보여드릴게요" 한 줄과 함께 책들이 각자 두께를 찾아가는 모습을 보여준다. 설명 없이 조용히 바뀌지 않게
- 두께 기준 재보정: 15권은 표본이 적어 30권쯤에서 구간 값을 한 번 다시 확인한다. 바뀌는 책이 있으면 한 줄 안내 (정책 버전 기록)
- 넓은 화면 기준: 한 칸에 8~10권을 보이게 두고 나머지는 옆으로 민다. 두께 구간은 짧음 28px / 보통 36px / 김 46px을 출발점으로, 새 탭 시안에서 확정한다
- 빛바램: 기사는 금방 식어서 짧은 구간을 촘촘하게. 여섯 단계를 색만으로 구분하기 어려워 디자인 단계에서 한 달 이후부터 먼지 같은 다른 표현을 섞는 방법을 검토한다
- 띠지 + 빛바램이 겹친 책 = 담아두고 한 번도 안 펼친 채 오래된 책 = 저녁 큐레이션 첫 번째 기준. 큐레이션 카드로 열어보면 띠지가 벗겨지면서 책장 모습도 바뀐다
- 포스트잇과 신간 띠지는 한 책에 같이 나타나지 않는다 (띠지는 안 펼친 책, 포스트잇은 읽고 메모한 책)
- 두께 = 분량은 읽기 전("지금 읽을 시간 되나?")에, 포스트잇 = 내 흔적은 읽은 후("내가 공들인 책")에 쓸모가 크다
- 신간 띠지는 "아직 안 읽음", 반짝임은 "방금 들어옴"으로 역할이 다르다

구현 메모
- 책 한 권 = 웹 화면의 세로 막대. 색 = 유형, 폭 = 두께
- 빛바램 = 채도·밝기를 단계별로 낮춤
- 신간 띠지 = 책등 가운데를 가로지르는 얇은 띠
- 포스트잇 = 책 위쪽으로 튀어나온 작은 색 조각
- 반짝임 = 카툰풍 별 서너 개, 0.8초
- 손글씨 = 한글 손글씨 웹폰트(나눔손글씨 펜, 개구 등, 확장에 파일로 포함), 인쇄 라벨 = 일반 글꼴
- 화면 표현은 어렵지 않다. 어려운 건 원문 수집과 분류 품질. 책이 수천 권으로 늘면 보이는 칸만 그리는 최적화가 필요하다

**9. 배열과 자리 안정성 (결정 7)**

칸 안 배열

| 순서 | 결과 |
|---|---|
| 담은 순서 (새 책이 오른쪽 끝) | 기본값. 신간 띠지가 오른쪽에 모이고 왼쪽으로 갈수록 빛이 바래 시간의 흐름이 그라데이션처럼 보임 |
| 발행 순서 | 정렬 바꾸기로 제공 |
| 많이 연 순서 | 정렬 바꾸기로 제공 (기본값으로 두면 위치 기억이 어려움) |
| 연결 중심 (다른 책과 많이 이어진 책을 가운데) | 정렬 바꾸기로 제공 |

- 칸마다 "정렬 바꾸기"와 유형 필터("이 칸에서 논문만 보기")를 같은 자리에 둔다

자리 안정성 원칙 (기억 축을 지키는 장치)
- 칸 안 배열은 담은 순서 고정. 많이 본 순 같은 자동 재정렬을 기본값으로 쓰지 않는다
- 규칙으로 책이 옮겨지려면 사용자 승인이 필요하다
- 이동 흔적: 원래 자리에 "이 책은 ○○ 칸으로 옮겨졌어요"를 일주일 남긴다
- 책을 닫으면 그 책이 꽂힌 자리가 보이는 상태로 돌아간다
- 칸 순서가 저절로 바뀌지 않는다. 내가 새 탭에서 끌어서 바꾸는 것은 된다. 처음 순서는 사서가 책이 많은 칸부터 정하고, 새 칸은 맨 뒤에 붙는다
- 어떤 기능을 넣든 "이게 책의 자리를 흔드나?"를 먼저 본다. 자동 정렬·인기순 노출·추천에 따른 재배치는 기본값으로 들어오지 못한다

기억 기능 후보: 모양으로 찾기(색·시기·포스트잇 유무 필터), 서재 산책(칸을 순서대로 훑기), 자리의 이야기("6개월 전 출근길에 담았어요")

**10. 책장 밖 공간 (별치)**

- 책상: 안 읽은 책 더미 → 신간 띠지로 대체
- 카트 → 임시서가
- 진열대: 전시 서가 (11절)
- 신착 서가: 수서해온 자료가 올라오는 자리 (01 4-5)
- 보존 서고: 내려둔 책. 책장에서는 안 보이고 검색하면 나온다. 추천·큐레이션·전시 후보에서 빠지고 칸 두께에도 안 세진다. 언제든 다시 서가로 올릴 수 있다. 책 삭제는 두지 않는다 (도서관 분위기). 크롬에서 북마크를 지워도 보존 서고로 내린다
- 대출 기록: 빌려준 책
- 같은 글을 두 번 담으면 한 권으로 합치고 메모는 모아둔다

**11. 전시 서가 (결정 9)**

출발점: 칸 축 발산의 "내 용도·질문 칸"(기간 한정 임시 칸). 사용자가 직접 만드는 대신 사서가 알아서 꾸리는 쪽으로 발전

기본 구조
- 위치: 책장 맨 앞 진열대. 책등 대신 표지가 보이게 세워둔다
- 넣는 방식: 진짜 책은 원래 주제 칸에 그대로 두고 전시에는 참조 카드로 꽂는다. 주제 칸 구조가 흐트러지지 않는다
- 시작: 서재에 책이 20권쯤 모이면 첫 전시
- 주기: 2주마다 교체
- 끝난 전시: 기록으로 남긴다. 모아 보면 관심사가 어떻게 흘러왔는지 연표처럼 보인다

주제 고르는 방법
- 먼저 묶고 이름만 LLM: 본문 임베딩으로 칸과 무관하게 묶고, 여러 칸이 섞인 무리 중 촘촘한 것을 고른다 (뼈대)
- 내 흔적에서: 최근 메모·하이라이트에 반복되는 말·질문에서 주제를 뽑는다 (가중치)
- LLM에게 통째로 맡기는 안은 돌릴 때마다 결과가 달라지고 뭉뚱그린 제목으로 흐르기 쉬워 제외

확정 흐름
1. 최근 2주 동안 담았거나 연 책을 후보로 모음 (코드)
2. 본문 임베딩으로 묶음 (코드)
3. 무리마다 점수를 매길 때 메모·하이라이트한 책이 많은 무리에 가산점 (코드)
4. 두 칸 이상이 섞였고 점수가 가장 높은 무리를 고름 (코드)
5. 그 무리에 질문형 제목과 책별 한 줄 이유를 붙임 (LLM)
6. 촘촘한 무리가 없으면 전시를 억지로 만들지 않고 지난 전시를 이어감

- 임베딩은 "다 읽으면 같이 읽을 책 꺼내주기"에도 필요해서 같은 재료를 두 기능이 함께 쓴다
- 제목을 질문형으로: "평가 자동화"처럼 이름만 붙이면 칸 이름과 비슷해진다. "자동 평가를 믿어도 될까?"처럼 질문으로 쓰면 여러 칸의 책이 한 질문에 답하는 구조가 보인다

보여주기 전 확인

| 실패 | 예시 | 확인 방법 |
|---|---|---|
| 칸 이름을 그대로 씀 | 제목이 "LLM 평가" | 기존 칸 이름과 같거나 거의 같으면 탈락 (코드) |
| 한 칸에서만 가져옴 | 5권 모두 같은 칸 | 2개 이상 칸에서 왔는지 확인 (코드) |
| 너무 넓음 | "AI는 어디로 가는가?" | 지난 전시 제목과 비교 (LLM) |
| 억지 연결 | 제목과 상관없는 책이 끼어 있음 | 책마다 따로 판정. 한 권이라도 억지면 빼거나 다시 생성 (LLM judge) |

- 억지 연결은 전시 전체를 한 번에 판정하기보다 책마다 따로 판정하는 쪽이 정확하다. 한 번에 보면 대부분 맞으니 넘어가기 쉽다

보여준 뒤 신호

| 신호 | 뜻 | 세기 | 무엇을 고치나 |
|---|---|---|---|
| 전시 책을 열어봄 | 주제가 끌림 | 중간. 같은 기간 일반 책 열람 비율과 비교해야 의미 있음 | 후보 뽑는 기준 (기간, 권수) |
| 전시 제목을 고침 | 사서가 흐름을 잘못 잡음 | 강함 | 제목 프롬프트. 고치기 전·후 제목 쌍이 반성 단계의 재료 |
| 전시에서 책을 뺌 | 그 책은 억지 연결 | 강함 | 책별 판정 기준. 뺀 책이 곧 판정 실패 사례 |
| 전시 기간에 관련 신간을 담음 | 관심이 이어짐 | 강함, 긍정 | 흐름 찾기가 맞았다는 근거 |
| 지난 전시를 다시 열어봄 | 기록으로 가치가 있음 | 약함 | 지난 전시 보관 방식 |

- 확인은 두 번: 보여주기 전(코드 + LLM judge)은 뻔한 실패를 거르고, 보여준 뒤(신호)는 통과한 전시가 실제로 맞았는지 본다
- 신호는 judge도 검증한다. judge가 통과시킨 책을 사용자가 뺐다면 judge 판단이 사용자 기준과 어긋난 것이다. 이런 사례가 쌓이면 judge 기준을 고친다. "Who Validates the Validators?"의 문제를 따로 채점하지 않고 사용하는 행동으로 푸는 구조

만드는 주체: 둘 다 가능하되 사서가 먼저
- 기본은 사서가 2주마다 전시를 꾸린다
- 전시 기간 2주 동안 한 번도 안 열어봤으면, 다음 회차에는 "이번엔 직접 꾸며보시겠어요?" 카드를 놓는다
- 그 카드도 그냥 두면 전시 기능은 4주 쉬고, 그 뒤 사서가 다시 한 번 시도한다
- 사용자가 직접 만든 전시(이름·기간 지정)는 그 주제와 책 구성이 사서의 정답 사례가 된다. 다음 회차부터 사서 전시 재개
- 진열대는 하나. 사서가 꾸린 전시는 인쇄 제목, 내가 꾸민 전시는 손글씨 제목
- 안 열어본 전시는 실패 사례로, 직접 만든 전시는 정답 사례로 쌓인다
- 직접 만들기가 있으면 선택하지 않은 장면 3("면접 전날 관련 글을 모아 복습")을 쓸 수 있다

**13. 저녁 큐레이션**

기준 후보 (여러 개를 섞음)
- 담아두고 한 번도 안 연 책 중 오래된 것
- 오늘 담은 책과 연결되는 예전 책
- 요즘 자주 여는 칸의 책
- 한동안 안 연 칸의 책 (잊고 있던 관심사 다시 꺼내기)
- 카드만 보고 넘겼던 책 중 지금 관심사와 가까워진 것
- (요일마다 기준을 바꾸는 방식도 가능)

전달 방식: 저녁에 새 탭을 열면 사서 자리에 카드, 또는 정해진 시간에 크롬 알림. 크롬 알림 권한은 이 기능을 붙일 때 요청한다

알고리즘은 사용자에게 숨긴다
- 이유를 모르고 받는 책이 더 설렌다. 도서관에서 찾던 책 옆 책을 우연히 발견하는 경험. 문헌정보학에서도 우연한 발견(serendipity)을 정보 탐색의 한 유형으로 연구한다
- 사용자에게는 숨기되 기록에는 남긴다. 카드마다 어떤 기준으로 뽑혔는지 로그에 있어야 자기개선 루프가 돈다

섞는 방식: 비중을 조절하는 추첨 (멀티암드 밴딧)
- 처음엔 모든 기준을 비슷한 비중으로
- 열어본 카드의 기준은 비중이 조금씩 오르고, 넘긴 카드의 기준은 내려간다
- 일정 비율은 항상 낯선 기준에 남겨둔다. 열어본 것만 따라가면 늘 비슷한 책만 오고 우연한 발견이 사라진다

흥미 유지 장치
- 같은 책이 연달아 오지 않게, 넘긴 책은 일정 기간 후보에서 제외
- 내 서재 안의 책만 오니까 너무 엉뚱하진 않다
- "이런 건 그만"을 누르면 그 기준 비중을 크게 낮춘다

이유 공개: **열어본 뒤 공개** (다른 후보였던 것: 끝까지 비밀, 힌트만)

| 뽑힌 기준 | 열어본 뒤 나오는 이유 |
|---|---|
| 담아두고 안 연 오래된 책 | "3주 전 출근길에 담아두고 잊고 계셨던 책이에요" |
| 오늘 담은 책과 연결 | "오늘 담으신 ○○와 같은 질문을 다룬 예전 책이에요" |
| 요즘 자주 여는 칸 | "요즘 자주 찾으시는 'LLM 평가' 칸의 책이에요" |
| 한동안 안 연 칸 | "두 달 동안 펼치지 않은 '추천 시스템' 칸에서 꺼내왔어요" |
| 카드만 보고 넘긴 책 | "지난번엔 카드만 보고 지나치셨는데, 요즘 관심사와 가까워졌어요" |

품질 관리
- 이유 문구 속 사실값("3주 전", "출근길", "두 달")을 LLM이 지어내면 안 된다
- 기준과 사실값: 로그와 DB에서 코드로 가져온다 (결정론적)
- 문장 다듬기: LLM이 자연스러운 말투로 (확률적)
- "이유 문구 속 사실이 실제 기록과 맞는가"를 코드로 바로 검사한다

공개 순간의 신호
- 이유를 보여준 직후 "이런 이유라면 좋아요" / "이건 별로" 반응을 받는다
- 책을 열었는지보다 어떤 이유가 마음에 들었는지를 직접 알려줘서 기준별 비중 조절에 더 정확한 재료가 된다

평가
- 기준별 열어본 비율, "이런 건 그만" 비율
- 열어본 비율만 올리면 안전한 책만 오게 되므로, 낯선 기준에서 온 책을 열어본 경우를 따로 세어 우연한 발견이 살아 있는지 확인한다

열린 질문: 기존 구상의 "저녁 요약"과 저녁 큐레이션을 하나로 합칠지 (허브)

**14. 지표**

분류와 규칙
- 칸 이동 비율 (자동 분류된 책을 다른 칸으로 옮긴 비율)
- 규칙 질문 수락률, 규칙 반영 후 같은 칸 이동 재발률
- 정답지 첫 제안 수락률 (사서 성능 출발점), 들어오는 글 버전별 정답지 유지율
- 분할 제안 수락률, 수락 시 사용자가 고친 정도(그대로 / 이름만 / 배치까지)
- 참조 카드 클릭률 (칸 관계 근거)
- 손글씨 이름표 칸 수의 변화 → 사서 신뢰도 지표

읽기와 요약
- 요약 재생성·수정 비율
- 읽기 품질 지표는 05

전시·큐레이션
- 전시 책 열람 비율 (같은 기간 일반 책 열람 비율과 비교), 제목 수정률, 책 제외율, 전시 기간 중 관련 신간 유입 수, 사서 전시 → 직접 만들기로 넘어간 횟수와 다시 사서 전시로 돌아온 횟수
- 큐레이션 기준별 열어본 비율, "이런 건 그만" 비율, 낯선 기준 열람 수

보여주는 자리: 사서 데스크(04 S34). 사서 일지에는 칸 이동 비율과 정답지 유지율을 숫자 옆 한 줄 풀이와 함께("지난달보다 칸 이동이 줄었어요") 보여주고, 칸별 기준 기록과 책마다 이 책이 걸어온 길을 함께 둔다. 숫자만 나열하면 대시보드가 되어 서재 분위기와 따로 논다
