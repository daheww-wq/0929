**0. 확정된 결정 요약**

1. 칸 축: 주제로만 칸을 나누고, 유형·분량·오래 안 연 정도는 책 모양(시각 기호)으로 표시. 출처·시기는 가리키면 뜨는 라벨. 관점은 태그로 달아 칸 안 배열에만 사용. 보기 전환은 필터 수준("이 칸에서 논문만 보기")
2. 여러 칸에 걸치는 책: 참조 카드. 진짜 책은 한 칸에만, 관련 칸에는 반투명 책·색인 카드. 한 책에 최대 2개
3. 첫 칸 생성과 신간 처리: 관심 주제로 넓은 칸 3~5개에서 시작. 신간은 확실하면 바로 해당 칸에 신간 띠지를 두르고 꽂고, 애매하면 임시서가로
4. 계층 깊이: 2단(책장 → 칸)으로 시작. 책장이 많아지면 사서가 방으로 묶기를 제안
5. 관리 권한: 설정 화면에서 모드를 고르는 대신, 평소엔 사서가 정리하고 사용자가 수정 버튼으로 손대는 순간 그 자리에서 권한이 넘어옴. 사서가 관리하는 칸은 인쇄 라벨, 내가 관리하는 칸은 손글씨 이름표 (자물쇠 표시는 닫힌 느낌이라 제외)
6. 책 표시: 책등 색 = 유형, 두께 = 분량(유형별 기준), 빛바램 = 마지막으로 펼친 뒤 지난 시간, 신간 띠지, 포스트잇 = 내 메모·하이라이트 (11번 상세)
7. 칸 안 배열: 담은 순서가 기본 (새 책이 오른쪽 끝). 정렬 바꾸기와 유형 필터 제공
8. 트리거 수치: 12번 표. 초기값이며 바꿀 때마다 정책 버전으로 기록
9. 전시 서가: 주제 칸과 별도로 책장 맨 앞 진열대. 사서가 2주마다 꾸리고, 사용자가 직접 만들 수도 있음 (13번 상세)

표기 원칙 (결정 5·9 공통): 사서가 만든 것은 인쇄 라벨, 내가 만든 것은 손글씨. 칸 이름표와 전시 제목 모두 같은 규칙을 따름. 별도 기호를 얹지 않고 글씨체만으로 구분되어 책장이 덜 복잡함

디자인 원칙: 무조건 시각적으로 예쁘게, 세련되게. 책 모양 시안은 기능 목록·범위를 정한 뒤 첫 버전 화면을 그릴 때 (디자인 단계)

기획과 디자인의 구분 (이 문서에서 쓰는 기준): "이게 바뀌면 동작·규칙·데이터가 바뀌는가?" 바뀌면 기획, 보이는 방식과 느낌만 바뀌면 디자인. 책 모양에 어떤 정보를 어떤 우선순위로 담을지는 기획, 색 팔레트·비율·표현 방식은 디자인

**1. 칸을 나누는 축 후보 (발산)**

| 축 | 칸 예시 | 도서관 원리 | 메모 |
|---|---|---|---|
| 주제 | LLM 평가, 추천 시스템, 프롬프트 | 분류기호 | 가장 기본 축 |
| 유형 | 논문, 기사, 리포트, 블로그 | 형식 패싯 | 칸보다 책등 색으로 표시하는 편이 어울림 |
| 관점 | 방법론, 사례, 비판·반론, 서베이 | 랑가나탄 PMEST의 Energy | 같은 주제 안의 2단 칸으로 쓸 만함 |
| 시기 | 발행 연도, 담은 달 | 시대 패싯(Time) | AI 분야는 시기에 따라 맥락이 크게 달라짐 |
| 출처 | arXiv, 언론사, 기업 블로그 | 출판 사항 | 필터로만 둬도 충분 |
| 내 용도 | 면접 준비, 포트폴리오, 개인 프로젝트 | 사용자 보증(user warrant) | 목적이 끝나면 칸이 사라지는 임시 칸 → 전시 서가로 발전 (13번) |
| 질문 | "LLM judge는 믿을 만한가?" | 연구 질문 중심 서지 | 전시 서가 제목을 질문형으로 짓는 데 반영 |
| 읽기 상태 | 안 읽음, 읽는 중, 다 읽음 | 신착 서가, 반납대 | 신간 띠지로 해결 |

**2. 여러 축을 책장에 얹는 방식 (발산)**

1. 단일 계층: 책장 = 대주제, 칸 = 중주제. 한 권은 한 칸에만. 가장 단순하고, 경계에 걸친 책이 문제
2. 청구기호식 조합: 칸은 주제 하나로 정하고, 유형은 책등 색, 출처는 라벨, 시기는 책 높이나 배열 순서로 표시. 한 화면에서 축 여러 개가 보임
3. 주 칸 + 참조 카드: 한 권은 한 칸에만 꽂히고, 관련 칸에는 "→ LLM 평가 칸에 있음" 색인 카드만 둠. 도서관의 "see also"와 같은 원리이고, 참조표의 확률적 실패(경계 주제)를 구조로 흡수
4. 패싯 책장: 칸은 고정 없이 보는 순간 축을 고르면 다시 배열됨. 유연하지만 "내 책장"이라는 공간 감각이 약해짐
5. 고정 칸 + 임시 칸: 주제 칸은 오래가고, 용도·질문 칸은 전시 서가처럼 기간 한정으로 만들었다가 해체

**3. 칸이 생기는 방식 (발산)**

1. 위에서 아래로: 처음에 내가 칸 5~8개를 직접 만들고 시작
2. 아래에서 위로: 빈 책장에 20권쯤 담은 뒤 LLM이 칸 구성을 제안. 문헌적 보증(literary warrant) 원리
3. 가져오기: 기존 노션·북마크 폴더를 읽어서 첫 칸 초안 제안
4. 자라는 칸: 넓은 칸 몇 개로 시작해 N권이 넘으면 분할 제안. 반대로 오래 두 권 이하인 칸은 합치기 제안

**4. 칸마다 붙일 정보 (통제 어휘)**

- 우선어: 칸 이름 하나로 통일 ("LLM 평가")
- 별칭(UF): LLM-as-a-Judge, 자동 평가, judge 모델 → 전부 이 칸으로
- 범위주기(scope note): "여기 들어오는 것 / 다른 칸으로 가는 것". 분류표의 포함·제외 주기와 같은 역할
- 상위·하위·관련 칸(BT/NT/RT): 칸 사이 관계. 참조 카드와 추천의 재료

자기개선 루프의 수정 단위 = 칸별 범위주기
- 참조표의 결정론적 실패 "매번 같은 칸에 잘못 꽂힘 → 칸 정의가 모호함"을 고치는 대상이 범위주기
- 프롬프트 전체 대신 옮긴 기록이 쌓인 칸의 범위주기만 LLM이 수정안을 내고 사용자가 승인
- 수정 범위가 작아 검증이 쉽고, 버전 관리도 칸 단위로 가능

**5. 칸 안의 배열 순서 (발산)**

담은 날짜순, 발행순, 저자순, 많이 연 순, 연결이 많은 책 가운데 배치 → 결정 7로 확정 (11번)

**6. 책장 밖 공간 (별치)**

- 책상: 안 읽은 책 더미 → 신간 띠지로 대체 (결정 3)
- 카트 → 임시서가로 확정 (결정 3)
- 진열대: 전시 서가 (결정 9, 13번)
- 보존 서고: 원본이 사라진 책 (장면 7)
- 대출 기록: 빌려준 책

**7. 실패 유형별 처리 경로 (사용자 제안에서 출발)**

| 구분 | 감지 방법 | 사서의 행동 |
|---|---|---|
| 결정론적 (매번 같은 칸으로 잘못 감) | 같은 칸 A→B 이동이 비슷한 책에서 3번 이상 반복, 재분류해도 같은 결과 | 규칙을 묻는 질문 → 확인 → 범위주기 수정 |
| 확률적 (돌릴 때마다 다른 칸) | 3회 분류 결과가 흔들림 | 규칙 질문 없이 임시서가로 |

- 규칙 질문은 결정론적 실패에만. 확률적 실패에 규칙 질문을 던지면 규칙이 계속 늘어나 범위주기가 누더기가 됨

규칙 질문 → 확인 → 수정 흐름
1. 질문: "최근 'LLM 평가'에 꽂힌 책 3권을 '에이전트' 칸으로 옮기셨어요. 에이전트를 평가하는 글은 앞으로 '에이전트' 칸에 둘까요?" (네, 앞으로 그렇게 / 이번 책들만 / 새 칸 만들기 '에이전트 평가')
2. 수정안 보여주기: 범위주기 변경 전후를 한 줄씩
3. 영향 미리보기: "이 규칙을 적용하면 기존 책 5권도 옮겨져요" + 목록. 자기개선 루프의 검증(회귀) 단계를 사용자 화면으로 옮긴 것
4. 승인 후 반영, 범위주기 버전 저장, 되돌리기 가능

- "이번 책들만" 응답도 기록. 규칙화하지 않겠다는 판단이라 같은 질문을 반복하지 않는 근거

질문 타이밍
- 읽는 중에는 묻지 않음. 책장을 열 때나 저녁 큐레이션 카드 옆에 모아서
- 한 번에 1~2개, 하루 상한 2개
- 큐레이션과 질문을 같은 사서 목소리로 전달

**8. 결정 상세 (결정 1~5)**

결정 1. 칸 축: 주제 칸 + 시각 기호

| 검토안 | 구조 | 결과 |
|---|---|---|
| A. 주제 칸 + 시각 기호 | 칸은 주제로만, 유형·출처·시기는 책 모양으로 | 채택 |
| B. 주제 + 관점 2단 | 주제 칸 안을 관점으로 한 번 더 나눔 | 관점은 태그로 흡수, 칸 안 배열에만 사용 |
| C. 보기 전환 | 유형별·질문별로 다시 늘어놓는 보기 | 필터 수준으로만 흡수 |

- 채택 이유: 사서(LLM)가 판단하는 건 주제 하나로 줄어 확률적 판단이 한 종류가 되고, 유형·출처·시기는 담을 때 뽑는 메타데이터라 코드로 검증 가능(결정론적). 판단 주체가 깔끔하게 나뉨
- 출처와 시기는 가리키면 뜨는 라벨

결정 2. 경계 책: 참조 카드

| 검토안 | 결과 |
|---|---|
| A. 참조 카드 (진짜 책 한 칸 + 관련 칸에 색인 카드) | 채택 |
| B. 복본 (여러 칸에 같은 책) | 칸 두께가 부풀고 원래 자리가 흐려져 제외 |
| C. 한 칸만 (경계 책은 사용자가 직접) | 관련 칸에서 안 보여 제외 |

- 시각: 칸 두께는 진짜 책만 셈. 반투명 책으로 "다른 칸에도 걸친 책"과 칸 사이 연결이 보임
- 품질: 3회 분류 결과가 흔들리면 가장 많이 나온 칸에 진짜 책, 두 번째 칸에 참조 카드. 확률적 실패를 정보로 사용
- 신호: 참조 카드를 눌러 책을 열었는지 기록 → 칸 관계(관련 칸)와 추천의 재료
- 규칙: 한 책에 참조 카드 최대 2개 / 참조 카드에서 진짜 책을 그 칸으로 옮기는 버튼 제공, 옮기면 분류 라벨로 기록 / 1등 칸도 확실하지 않으면 임시서가로

결정 3. 첫 칸 생성과 신간 처리

- 검토 과정: 위에서 아래 + 아래에서 위 혼합안(바닥에 20권 쌓였다가 첫 정리)을 제안했으나, 정리 없이 쌓아두는 단계는 앱 취지와 맞지 않아 제외. 가져오기는 당시 "필요성부터 재검토"였으나 2026-09-23 크롬 확장 전환으로 북마크 가져오기가 첫 버전 주 입구가 됨 (노션은 후보로 남음)
- 확정 흐름
  1. 시작할 때 관심 주제를 적으면 사서가 넓은 칸 3~5개 초안을 만듦
  2. 신간은 확실도에 따라 두 갈래

| 경우 | 가는 곳 | 보이는 모습 |
|---|---|---|
| 확실히 구분됨 | 바로 해당 칸으로 | 신간 띠지를 두른 채 꽂힘 |
| 애매함 / 맞는 칸 없음 | 임시서가 | 사서가 붙인 칸 이름 후보와 함께 대기 |

  3. 임시서가에 같은 무리가 3권 모이면 새 칸 제안, 오래 혼자 남은 책은 가까운 칸으로 옮기자고 제안
  4. 그 뒤로는 칸이 두꺼워질 때마다 분할 제안
- "확실함" 기준: 3번 분류해서 3번 모두 같은 칸이 나오고, 그 칸의 범위주기와도 맞을 때
- 신간 띠지: 펼쳐보면 벗겨짐. 띠지 두른 책 = 안 읽은 새 책 → 장면 2(쌓인 글 훑기)와 저녁 큐레이션 후보를 책장에서 바로 확인. 칸별 띠지 수로 요즘 많이 담는 주제가 보임
- 첫 정답 세트: 처음 20권은 두 갈래 모두 "○○ 칸에 꽂았어요" 확인을 받는다. 확인은 새 탭의 사서 자리에 쌓이고, 사용자가 그대로 두거나 옮긴다. 이 20권이 분류 검증 세트의 첫 정답. 이후 범위주기를 바꿀 때마다 이 20권으로 회귀 확인. 첫 제안 수락률은 사서 성능의 출발점 수치. 21권째부터는 확인 없이 조용히 꽂힘
- 확인을 며칠 지나도록 열어보지 않으면 사서 판단대로 둔다 (2026-09-23 수정: 담기가 북마크로 바뀌어 담는 순간 뜨는 화면이 없다)

결정 4. 계층 깊이: 2단 시작

| 검토안 | 결과 |
|---|---|
| 2단: 책장(대주제) → 칸 | 시작 구조로 채택 |
| 3단: 방(분야) → 책장 → 칸 | 처음부터는 두지 않음 |
| 2단 시작, 필요할 때 3단 | 책장이 많아지면 사서가 방으로 묶기를 제안 |

- 방이 생기더라도 서재 전체가 한 화면에 보이는 전체 보기는 남겨둠

결정 5. 관리 권한: 수정하는 순간 넘어오는 방식

- 검토 과정
  - 처음 안: 시작할 때 모드 선택 (직접 관리 / 사서에게 맡김 / 반반). 직접 관리 모드에서도 사서가 칸 분할을 제안하기로 확정
  - 두 번째 안: 모드 대신 단계별 스위치 두 개 (책장, 칸)
  - 최종: 설정 화면 없이, 평소엔 사서가 정리하고 사용자가 수정 버튼을 누르는 순간 그 자리에서 권한이 넘어옴
- 흐름
  1. 기본: 책 배치와 칸 관리는 사서가. 새 칸 만들기·분할처럼 구조가 바뀔 때만 제안
  2. 수정: 책장·칸·책 어디서든 수정 버튼으로 직접 바꿈
  3. 바꾼 직후 사서가 한 번 질문: "이번만 바꿀게요" / "앞으로도 이런 책은 이렇게"(범위주기 수정) / "이 칸은 앞으로 제가 직접 관리할게요"(권한 이전)
  4. 직접 관리하는 칸은 손글씨 이름표로 바뀜 (사서가 관리하는 칸은 인쇄 라벨). 사서는 그 칸 구조를 건드리지 않고, 두꺼워지면 분할 제안만
- 표시 검토: 자물쇠는 잠겨서 닫힌 느낌이라 제외. 압정/핀, 리본·책갈피 대신 손글씨 이름표 채택. 기호를 얹지 않고 라벨 자체가 달라져 책장이 덜 복잡함
- 모든 수정마다 묻지는 않음

| 수정 | 사서의 반응 |
|---|---|
| 책 한 권 옮기기 | 묻지 않고 기록만. 같은 방향 이동이 반복되면 규칙 질문 (7번) |
| 칸 이름 바꾸기, 칸 나누기·합치기 | 바로 질문 |
| 책장 수준 변경 | 바로 질문 |

- 방금 고친 순간이라 맥락이 살아 있어 답하기 쉽고, "읽는 중에는 묻지 않기" 원칙과도 부딪히지 않음 (편집 중이므로)

분할 제안 (모든 칸 공통, 손글씨 이름표 칸 포함)
- 트리거: 12번 표
- 제안에 담을 것: 새 칸 이름 2개, 각 칸 범위주기 초안, 책 배치안, "나중에" 버튼
- 사서가 관리하는 칸: 승인하면 사서가 제안대로 반영
- 손글씨 이름표 칸: 사용자가 칸 이름·책 배치를 고쳐서 확정
- 거절 시 2주 동안 같은 칸 제안 보류

**11. 책 표시와 칸 안 배열 (결정 6·7 상세)**

책 표시 확정

| 대상 | 표시 | 뜻 | 값 구간 | 데이터 출처 | 시작 시점 |
|---|---|---|---|---|---|
| 책 | 책등 색 | 유형 | 논문 / 기사 / 리포트·기타 (3색) | 메타데이터 (코드) | 첫날 |
| 책 | 두께 | 분량 (유형별 기준) | 짧음 / 보통 / 김. 기사는 글자 수, 논문은 페이지 수로 각각 나누고, 구간 값은 처음 담은 15권의 분포를 보고 정함 | 본문 글자 수·페이지 수 (코드) | 15권 뒤, 바뀌는 순간을 보여주며 |
| 책 | 빛바램 | 마지막으로 펼친 뒤 지난 시간 | 없음(7일 미만) / 7일 / 14일 / 한 달 / 세 달 / 반년 이상 | 열람 로그 (코드) | 첫날 |
| 책 | 신간 띠지 | 아직 안 펼친 새 책 | 있음 / 없음 | 열람 로그 (코드) | 첫날 |
| 책 | 포스트잇 | 내 메모·하이라이트 | 1~3개 (메모 수에 따라 늘고 3개에서 멈춤). 튀어나오는 위치 = 하이라이트한 본문 위치 | 메모·하이라이트 기록 | 첫날 |
| 책 | 반투명 | 참조 카드 (진짜 책은 다른 칸에) | 있음 / 없음 | 분류 결과 (LLM) | 첫날 |
| 칸 | 손글씨 이름표 / 인쇄 라벨 | 내가 관리하는 칸 / 사서가 관리하는 칸 | 둘 중 하나 | 사용자 수정 기록 | 첫날 |
| 칸 | 점선 칸 | 임시서가 | 있음 / 없음 | 분류 결과 | 첫날 |
| 전시 | 손글씨 제목 / 인쇄 제목 | 내가 꾸민 전시 / 사서가 꾸민 전시 | 둘 중 하나 | 전시 생성 주체 | 첫 전시부터 |

눈에 들어오는 순서 (우선순위)
1. 신간 띠지 → 2. 빛바램 → 3. 책등 색 → 4. 두께

표시 설계 메모
- 분량 검토: 시간 하나로 자르면 기사는 전부 "짧음", 논문은 전부 "김"이 되어 두께가 유형을 한 번 더 보여주게 됨. 검토안 A(유형별 기준) 채택, B(내 서재 안 상대 비교)는 책이 늘면 같은 책 두께가 저절로 바뀌어 제외, C(두께 = 내 흔적)는 포스트잇으로 흡수
- 두께 적용 시점: 처음 15권은 모든 책을 같은 두께로 두고, 15권이 모이는 날 "이제 책 두께로 분량을 보여드릴게요" 한 줄과 함께 책들이 각자 두께를 찾아가는 모습을 보여줌. 설명 없이 조용히 바뀌지 않게
- 두께 기준 재보정: 15권은 표본이 적어 30권쯤에서 구간 값을 한 번 다시 확인. 바뀌는 책이 있으면 한 줄 안내 (정책 버전 기록)
- 빛바램 단계: 기사는 금방 식어서 짧은 구간을 촘촘하게. 여섯 단계를 색만으로 구분하기 어려워 디자인 단계에서 한 달 이후부터 먼지 같은 다른 표현을 섞는 방법 검토
- 띠지 + 빛바램이 겹친 책 = 담아두고 한 번도 안 펼친 채 오래된 책 = 저녁 큐레이션 첫 번째 기준. 큐레이션 카드로 열어보면 띠지가 벗겨지면서 책장 모습도 바뀜
- 포스트잇과 신간 띠지는 한 책에 같이 나타나지 않음 (띠지는 안 펼친 책, 포스트잇은 읽고 메모한 책). 포스트잇은 첫날부터 보여서 두께 적용 전에도 책장이 조금씩 달라짐
- 두께 = 분량은 읽기 전("지금 읽을 시간 되나?")에, 포스트잇 = 내 흔적은 읽은 후("내가 공들인 책")에 쓸모가 큼
- 손글씨 / 인쇄 구분은 칸 이름표와 전시 제목에 같은 규칙으로 적용 (0번 표기 원칙)

구현 메모 (가능 여부 확인)
- 책 한 권 = 웹 화면의 세로 막대. 색 = 유형, 폭 = 두께
- 빛바램 = 채도·밝기를 단계별로 낮춤
- 신간 띠지 = 책등 가운데를 가로지르는 얇은 띠
- 포스트잇 = 책 위쪽으로 튀어나온 작은 색 조각
- 손글씨 = 한글 손글씨 웹폰트(구글 폰트 나눔손글씨 펜, 개구 등), 인쇄 라벨 = 일반 글꼴
- 화면 표현은 어렵지 않음. 이 앱에서 어려운 건 원문 수집과 분류 품질. 책이 수천 권으로 늘면 보이는 칸만 그리는 최적화 필요

칸 안 배열 (결정 7)

| 검토안 | 순서 | 결과 |

| A. 담은 순서 | 새 책이 오른쪽 끝에 꽂힘 | 기본값으로 채택. 신간 띠지가 오른쪽에 모이고 왼쪽으로 갈수록 빛이 바래 시간의 흐름이 그라데이션처럼 보임 |
| B. 발행 순서 | 발행일 순 | 정렬 바꾸기로 제공 |

| D. 연결 중심 | 다른 책과 많이 이어진 책을 가운데에 | 정렬 바꾸기로 제공 |

- 칸마다 "정렬 바꾸기"와 유형 필터("이 칸에서 논문만 보기")를 같은 자리에

**13. 전시 서가 (결정 9)**

출발점: 칸 축 발산의 "내 용도·질문 칸"(기간 한정 임시 칸). 사용자가 직접 만드는 대신 사서가 알아서 꾸리는 쪽으로 발전

기본 구조
- 위치: 책장 맨 앞 진열대. 책등 대신 표지가 보이게 세워둠
- 넣는 방식: 진짜 책은 원래 주제 칸에 그대로 두고 전시에는 참조 카드로 꽂음. 주제 칸 구조가 흐트러지지 않음
- 시작: 서재에 책이 20권쯤 모이면 첫 전시
- 주기: 2주마다 교체
- 끝난 전시: 기록으로 남김. 모아 보면 관심사가 어떻게 흘러왔는지 연표처럼 보임

주제 고르는 방법 (검토안 B + C)

| 검토안 | 방법 | 결과 |
|---|---|---|
| A. LLM에게 통째로 | 최근 책 요약을 주고 공통 질문을 찾게 함 | 돌릴 때마다 결과가 달라지고 뭉뚱그린 제목으로 흐르기 쉬워 제외 |
| B. 먼저 묶고 이름만 LLM | 본문 임베딩으로 칸과 무관하게 묶고, 여러 칸이 섞인 무리 중 촘촘한 것을 고름 | 뼈대로 채택 |
| C. 내 흔적에서 | 최근 메모·하이라이트에 반복되는 말·질문에서 주제를 뽑음 | 가중치로 채택 |

확정 흐름
1. 최근 2주 동안 담았거나 연 책을 후보로 모음 (코드)
2. 본문 임베딩으로 묶음 (코드)
3. 무리마다 점수를 매길 때 메모·하이라이트한 책이 많은 무리에 가산점 (코드)
4. 두 칸 이상이 섞였고 점수가 가장 높은 무리를 고름 (코드)
5. 그 무리에 질문형 제목과 책별 한 줄 이유를 붙임 (LLM)
6. 촘촘한 무리가 없으면 전시를 억지로 만들지 않고 지난 전시를 이어감

- 임베딩은 장면 8("다 읽으면 같이 읽을 책 꺼내주기")에도 필요해서 같은 재료를 두 기능이 함께 씀
- 제목을 질문형으로: "평가 자동화"처럼 이름만 붙이면 칸 이름과 비슷해짐. "자동 평가를 믿어도 될까?"처럼 질문으로 쓰면 여러 칸의 책이 한 질문에 답하는 구조가 보임. 칸 축 발산의 "질문 칸" 아이디어가 여기서 살아남

보여주기 전 확인

| 실패 | 예시 | 확인 방법 |
|---|---|---|
| 칸 이름을 그대로 씀 | 제목이 "LLM 평가" | 기존 칸 이름과 같거나 거의 같으면 탈락 (코드) |
| 한 칸에서만 가져옴 | 5권 모두 같은 칸 | 2개 이상 칸에서 왔는지 확인 (코드) |
| 너무 넓음 | "AI는 어디로 가는가?" | 지난 전시 제목과 비교 (LLM) |
| 억지 연결 | 제목과 상관없는 책이 끼어 있음 | 책마다 따로 판정. 한 권이라도 억지면 빼거나 다시 생성 (LLM judge) |

- 억지 연결은 전시 전체를 한 번에 판정하기보다 책마다 따로 판정하는 쪽이 정확함. 한 번에 보면 대부분 맞으니 넘어가기 쉬움

보여준 뒤 신호

| 신호 | 뜻 | 세기 | 무엇을 고치나 |
|---|---|---|---|
| 전시 책을 열어봄 | 주제가 끌림 | 중간. 같은 기간 일반 책 열람 비율과 비교해야 의미 있음 | 후보 뽑는 기준 (기간, 권수) |
| 전시 제목을 고침 | 사서가 흐름을 잘못 잡음 | 강함 | 제목 프롬프트. 고치기 전·후 제목 쌍이 반성 단계의 재료 |
| 전시에서 책을 뺌 | 그 책은 억지 연결 | 강함 | 책별 판정 기준. 뺀 책이 곧 판정 실패 사례 |
| 전시 기간에 관련 신간을 담음 | 관심이 이어짐 | 강함, 긍정 | 흐름 찾기가 맞았다는 근거 |
| 지난 전시를 다시 열어봄 | 기록으로 가치가 있음 | 약함 | 지난 전시 보관 방식 |

- 확인은 두 번: 보여주기 전(코드 + LLM judge)은 뻔한 실패를 거르고, 보여준 뒤(신호)는 통과한 전시가 실제로 맞았는지 봄
- 신호는 judge도 검증함. judge가 통과시킨 책을 사용자가 뺐다면 judge 판단이 사용자 기준과 어긋난 것. 이런 사례가 쌓이면 judge 기준을 고침. "Who Validates the Validators?"의 문제를 따로 채점하지 않고 사용하는 행동으로 푸는 구조

만드는 주체: 둘 다 가능하되 사서가 먼저
- 기본은 사서가 2주마다 전시를 꾸림
- 전시 기간 2주 동안 한 번도 안 열어봤으면, 다음 회차에는 사서가 만드는 대신 "이번엔 직접 꾸며보시겠어요?" 카드를 놓음
- 그 카드도 그냥 두면 전시 기능은 4주 쉬고, 그 뒤 사서가 다시 한 번 시도
- 사용자가 직접 만든 전시(이름·기간 지정)는 그 주제와 책 구성이 사서의 정답 사례가 됨. 다음 회차부터 사서 전시 재개
- 진열대는 하나. 전시 제목의 글씨체로 구분함: 사서가 꾸린 전시는 인쇄 제목, 내가 꾸민 전시는 손글씨 제목. 칸 이름표 규칙과 같음 (0번 표기 원칙)
- 안 열어본 전시는 실패 사례로, 직접 만든 전시는 정답 사례로 쌓임
- 직접 만들기가 있으면 선택하지 않은 장면 3("면접 전날 관련 글을 모아 복습")을 쓸 수 있음

전시 지표
- 전시 책 열람 비율 (같은 기간 일반 책 열람 비율과 비교)
- 제목 수정률, 책 제외율
- 전시 기간 중 관련 신간 유입 수
- 사서 전시 → 직접 만들기로 넘어간 횟수, 다시 사서 전시로 돌아온 횟수
