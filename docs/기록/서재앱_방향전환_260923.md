**서재앱 방향 전환 (2026-09-23)**

첫 버전의 형태를 폰 중심 PWA에서 크롬 확장(새 탭이 곧 서재)으로 바꾼 기록. 이 문서가 현재 기준이고, 이전 문서와 어긋나는 부분은 여기가 우선한다.

---

**1. 왜 바뀌었나**

- 폰 390픽셀에서는 책장이 답답했다. 책등이 좁아 한글 제목이 들어가지 않고, 서재다운 공간감도 살지 않았다
- 앱을 다시 열 이유를 따로 만들어야 했다. 새 탭은 하루에 수십 번 열리므로 그 고민이 사라진다
- 크롬 북마크를 읽을 방법이 없어 가져오기를 첫 버전에서 뺐는데, 확장이면 북마크를 직접 읽고 쓸 수 있다
- 원문 페이지 위에서 하이라이트할 수 있어, 로그인·유료 기사에서도 해석이 쌓인다

**2. 바뀐 것 12가지**

| # | 항목 | 이전 | 지금 |
|---|---|---|---|
| 1 | 만드는 형태 | 폰 중심 PWA | 크롬 확장. 새 탭이 서재. 폰 PWA는 다음 단계 |
| 2 | 담는 경로 | iOS 단축어 | 북마크가 곧 담기. 확장 버튼이 보조, 단축어는 폰용 |
| 3 | 가져오기 | 첫 버전 제외 | 핵심 입구로 승격 |
| 4 | 첫 화면 | 서재 전체 보기 | 새 탭 대시보드 (책장 + 사서 + 할 일) |
| 5 | 할 일 트래커 | 없음 | 새로 추가 |
| 6 | 포지셔닝 | 해석 + 성장 | "나를 배워가는 사서"로 좁힘 |
| 7 | 사서 | 사람 일러스트 | 집사 고양이. 파츠 조합, 시간대와 상태에 따라 움직임 |
| 8 | 하이라이트 | 저장본에서만 | 원문 페이지 위에서도. 양쪽이 같은 기록 |
| 9 | 로그인·유료 기사 | 링크와 메모만 (C등급) | 보고 있는 화면을 쓸 수 있어 하이라이트까지 가능 |
| 10 | 3D 서재 | 첫 화면 후보 | 별도 화면. 새 탭은 가볍게 떠야 함 |
| 11 | 화면 기술 | Next.js + Vercel | Vite + React를 확장에 번들. 3D 라이브러리와 폰트도 번들 |
| 12 | 로그인 | 이메일 매직 링크 | 서버가 발급한 키를 확장에 저장 |

**3. 확장이 맡는 범위**

서재 전체가 확장 안에 들어간다. 화면은 셋.

- 새 탭: 책장, 사서, 할 일, 검색
- 읽기 뷰어: 저장한 본문을 읽고 하이라이트·메모·용어 설명
- 3D 서재: "서재 들어가기"를 눌렀을 때만

여기에 원문 페이지 위에 얹히는 작은 도구 모음(문장 선택 시 하이라이트/메모/용어 설명)이 더해진다. 화면이라기보다 떠 있는 메뉴다.

**4. 폰은 어떻게 되나**

아이폰 크롬은 확장을 지원하지 않는다. 그래서 폰에서 직접 담는 건 iOS 단축어로 남긴다. 폰 크롬에서 북마크한 글은 크롬 계정 동기화로 PC에 내려오고, PC 크롬이 켜질 때 확장이 담는다. 출근길 장면은 시차를 두고 유지된다. 사파리 북마크는 크롬과 별개라 들어오지 않는다.

폰에서 읽고 메모하는 것은 다음 단계의 PWA가 맡는다. 서버와 데이터는 같은 것을 쓰므로 다시 만들 것은 화면뿐이다.

**5. 북마크 동기화 규칙**

| 상황 | 처리 |
|---|---|
| 설치 시점 | 기존 북마크는 담지 않는다. 제목·주소·폴더·추가일만 읽어 목록으로 보관 |
| 설치 이후 새 북마크 | 자동으로 담긴다 |
| 기존 북마크 | 사서가 폴더 단위로 제안한다. 승인하면 동시에 두세 개씩 천천히 수집 |
| 가져오기 전 | 주소만으로 살아 있는지 먼저 확인하고, 죽은 링크는 따로 모아 아카이브를 권한다 |
| 자동 담기 범위 | 지정한 폴더만 담도록 설정 가능. 기본은 모든 새 북마크 |
| 북마크 삭제 | 서재에서는 지우지 않고 보존 서고로 내린다 |
| 북마크 폴더 이동 | 첫 버전은 무시. 나중에 "칸도 옮길까요?"로 묻는다 |
| 같은 주소 재북마크 | 새 책을 만들지 않고 기존 책에 합친다 |

북마크와 서재는 따로 운영되고 한 방향으로 흐른다. 북마크는 주소 한 줄이고, 서재는 원문·요약·메모·분류를 담는다. 서재에서 담은 책을 북마크에 추가하는 것은 기본으로 꺼두고, 원하면 "서재" 폴더에 자동 추가로 켠다. 크롬 북마크 구조는 사용자의 기존 습관이므로 함부로 바꾸지 않는다.

**6. 하이라이트와 메모**

두 자리에서 가능하다.

- 원문 웹페이지: 확장이 얹혀서 문장을 선택하면 작은 메뉴가 뜬다
- 읽기 뷰어: 저장한 본문 위에서 같은 방식

위치는 세 가지를 함께 저장해 복원한다. 선택한 문장 그대로, 앞뒤 30자, 몇 번째 문단인지. 같은 문장을 저장본에서도 찾아 위치를 계산해두므로, 원문에서 그은 하이라이트가 뷰어·메모 모아보기·책등 포스트잇에 모두 반영된다. 찾지 못하면 지우지 않고 "위치를 찾지 못했어요"로 남긴다.

원문이 사라져도 저장본 위치로 옮겨져 있어 하이라이트는 남는다. PDF는 크롬 기본 뷰어 대신 우리 뷰어로 열어야 하이라이트가 된다. 폰(PWA)에서는 저장본에서만 가능하다.

**7. 읽기 등급이 달라진 부분**

읽기 등급은 세 단계다 (정의와 화면 처리는 `서재앱_화면설계서.md` 0절).

| 등급 | 상태 | 할 수 있는 것 |
|---|---|---|
| A | 본문을 깨끗하게 뽑음 | 텍스트 모드 읽기, 하이라이트, 메모, 용어 설명, 요약 |
| B | 본문은 못 뽑고 화면은 남김 | 원문 모드 읽기, 책 전체 메모 |
| C | 원문을 못 가져옴 | 링크 + 메모 + 아카이브 주소 |

로그인·유료 기사가 C등급(링크와 메모만)에서 A로 올라간다. 확장이 내가 보고 있는 화면을 읽을 수 있기 때문이다. 다만 서버가 자동으로 가져오지는 못하므로, 해당 기사는 "내가 열어둔 상태에서 담기"가 전제다. 읽기 품질 스파이크도 이 경로를 포함해 다시 설계한다.

**8. 기술 스택 변화**

| 부분 | 그대로 | 바뀜 |
|---|---|---|
| 수집·추출 (trafilatura, Playwright) | 그대로 | |
| API 서버 (FastAPI, Railway) | 그대로 | 확장 주소 허용 설정 추가 |
| DB (관리형 Postgres) | 그대로 | |

| LLM 호출 | 그대로 | |
| 마크다운 내보내기·옵시디언 | 그대로 | |
| 화면 | | Next.js + Vercel → Vite + React, 확장에 번들 |
| 로그인 | | 매직 링크 → 서버 발급 키를 확장에 저장 |

새로 필요한 것: 확장 기본 파일 한 세트(설정 파일, 새 탭 페이지, 백그라운드 스크립트), 북마크를 읽어오는 코드.

비용은 그대로 월 1만 원 안쪽. 혼자 쓸 때는 스토어 등록 없이 개발자 모드로 설치하면 된다. 등록할 때는 북마크 권한 사유를 설명해야 한다.

**9. 포지셔닝**

한 문장: **쓸수록 내 기준을 아는 사서가 생기는 서재**

- 해석(메모와 하이라이트가 남는 것)과 성장(분류 기준이 자라는 것)은 이 안에 들어간다
- 첫 화면의 주인공은 책장이 아니라 사서다. 새 탭을 열 때마다 사서가 무언가 하고 있다
- 20권 정답 세트가 약속이 된다. "스무 권이면 당신의 사서가 생깁니다"
- 서재 기록 화면은 부속이 아니라 핵심이다. 사서가 나를 얼마나 알게 됐는지 보는 화면이다
- 3D 서재는 배경이고, 관계가 앞에 선다

비슷한 도구들(Momentum·Tabliss의 새 탭, Toby·Workona의 탭 정리, Raindrop의 북마크, Hypothesis·Glasp·Liner의 하이라이트)은 저장과 정리를 사람이 한다. 북마크를 사서가 분류하고, 내가 고치면 기준이 자라는 구조는 아직 없다.

**10. 사서**

집사 고양이. 사람 일러스트는 호불호가 크고 표정 컷을 여러 장 그려야 해서 접었다.

파츠 조합으로 상태를 만든다. 귀(평소/쫑긋/눕힘), 눈(뜸/반달/감음/곁눈질), 꼬리(말림/살랑/곧게), 손(빈손/책/돋보기/리본). 그림을 여러 장 그리지 않아도 상태가 다 나온다.

새 탭을 열 때마다 사서가 무언가 하고 있다.
- 아침: "어제 담은 세 권 정리해뒀어요"
- 수집 중: 책을 안고 선반으로 걸어가는 중
- 물어볼 게 있을 때: 고개를 들고 말풍선
- 실패가 있을 때: 귀를 눕히고 "두 건은 못 가져왔어요"
- 아무 일 없을 때: 선반 위에서 꼬리만 살랑이며 졸기
- 저녁: 램프를 켜고 "오늘 이 책은 어떠세요"

규칙: 조용한 상태가 기본이고 말을 거는 건 하루 두 번까지. 기다리는 동안 실제로 움직인다. 결과를 보고한다. 내가 고치면 반응한다. 시간을 안다.

그래픽 예산은 사서에 몰고, 책장과 목록은 단순한 도형과 글자로 간다.

**11. 그대로 유지되는 것**

책장 구조 결정 9개(칸 축, 참조 카드, 신간·임시서가, 계층, 관리 권한, 책 표시, 배열, 트리거 수치, 전시 서가), 범위주기와 규칙 질문, 첫 20권 정답 세트와 회귀 확인, 자리 안정성 원칙, 저작권 판단, 아카이빙, 저녁 큐레이션(알림은 크롬 알림으로), 검색과 백업, 옵시디언 마크다운 공존, 증상-원인-확인법 참조표.

책장 구조에서 한 가지만 다시 잡는다. 책등 폭과 한 칸에 보이는 권수는 폰이 아니라 넓은 화면 기준이다.

**12. 무효가 된 것**

- 온보딩의 "홈 화면에 추가"와 "단축어 설치"가 주 경로였던 부분 → 확장 설치와 북마크 폴더 선택으로 바뀐다
- 담기 흐름의 "공유 시트 → 단축어" 1~2단계 → 북마크 생성 이벤트로 바뀐다
- 화면 목록의 폰 기준 구성 → 새 탭·뷰어·3D 서재·원문 위 도구 모음으로 다시 정리한다
- 첫 버전 완료 기준 1번("링크를 공유해서 담으면") → "북마크하면 담기고 칸에 꽂힌다"로
- 크롬 북마크 가져오기를 "첫 버전 제외"로 둔 판단
