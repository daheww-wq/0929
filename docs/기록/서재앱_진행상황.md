**3. 확정된 핵심 결정**

만드는 형태
- 크롬 확장. 새 탭이 서재, 읽기 뷰어, 3D 서재가 확장 안 화면. 원문 페이지 위에는 선택 도구 모음
- 담기는 북마크. 설치 이후 새 북마크는 자동, 기존 북마크는 폴더 단위로 사서가 제안
- 폰은 단축어로 담고, 폰 크롬 북마크는 PC를 켤 때 동기화로 들어옴
- 저장은 서버(관리형 서비스 조합), 화면만 Vite + React로 확장에 번들

책장
- 칸은 주제로만, 유형·분량·오래 안 연 정도는 책 모양으로
- 경계 책은 참조 카드, 애매한 신간은 임시서가, 확실하면 신간 띠지
- 2단(책장 → 칸) 시작, 책장이 많아지면 방으로 묶기 제안
- 평소엔 사서가 정리하고, 수정 버튼을 누르는 순간 권한이 넘어옴
- 사서가 만든 것은 인쇄 라벨, 내가 만든 것은 손글씨
- 책 삭제 없음. 보존 서고로 내림
- 자리 안정성 원칙: 책의 자리가 저절로 바뀌지 않음

사서
- 집사 고양이. 파츠 조합으로 상태를 표현. 하루 두 번까지만 말을 검
- 결정론적 실패는 규칙 질문 → 확인 → 범위주기 수정, 확률적 실패는 참조 카드·임시서가
- 규칙 반영 전에 영향 미리보기와 첫 20권 정답 세트 회귀 확인
- 전시 서가는 2주마다. 주제 선정은 계산, 제목은 LLM

첫 버전 완료 기준 (전환 반영)
1. 북마크하면 원문이 저장되고 칸에 꽂힌다
2. 20권을 담아 첫 정답 세트가 만들어진다
3. 새 탭에서 책장과 사서가 보이고, 안 읽은 책을 훑어 읽을 수 있다
4. 원문 페이지와 읽기 뷰어 양쪽에서 하이라이트·메모·용어 설명이 남고, 상호대차로 새 책이 들어온다
5. 책을 세 번 옮기면 사서가 규칙을 묻고, 승인하면 범위주기가 바뀌고 되돌릴 수 있다

범위를 잠근 뒤 바꾸는 규칙: 새 아이디어는 다음 버전 후보로. 첫 버전에 넣으려면 대신 뺄 것을 하나 정한다

**4. 아직 안 정한 것**

- 영상도 담을지
- 저녁 요약(기존 구상)과 저녁 큐레이션을 하나로 합칠지
- 친구 공유를 언제 넣을지 (현재 셋째 단계)
- 할 일 트래커의 범위 (단순 체크리스트인지, 책과 연결되는지)
- 3D 서재를 첫 버전에 넣을지
- 서비스 이름
- 서재 전체 보기의 모양 (세로로 이어진 서가 / 칸 카드 넘기기 / 전체 보기 없이 칸부터)
- 노션 가져오기 (크롬 북마크는 첫 버전으로 승격됨)
- 칸을 방으로 묶는 기준 (넓은 화면이라 칸이 한눈에 들어와 보류)

해소된 열린 질문
- Phase 앱과 합칠지 → 마크다운으로 저장해 옵시디언과 공존하기로 하면서 같은 길이 됨

**5. 포트폴리오로 쓸 수 있는 지점**

- 전공 지식(분류 체계, 통제 어휘, 문헌적 보증, 웹 아카이빙, LOCKSS)을 제품 설계에 적용
- 결정론적 실패는 규칙으로, 확률적 실패는 개별 판단으로 나눈 처리 경로
- LLM 판단과 코드 검증을 설계 단계에서 분리
- 첫 20권 확인이 별도 라벨링 없이 검증 세트가 되는 구조
- 사용자 행동으로 judge 판단까지 검증하는 구조
- 사용자 규모 대신 개선 과정 지표로 성과 제시
- 기획과 디자인의 경계를 "동작·규칙·데이터가 바뀌는가"로 나눠 순서대로 진행
- 만들던 중에 방향을 튼 판단과 그 근거 (폰 PWA → 크롬 확장)
