**0. 정한 것**

1. 기능 목록을 첫 버전 / 다음 버전 / 그다음 / 후보로 나눔
2. 기능 목록만으로는 놓치는 것이 있어, 첫 버전 후보를 흐름 다섯 개로 펼쳐 점검함 (시작하기, 담기, 훑고 읽기, 메모하기, 고치기)
3. 온보딩 항목: 이름(필수) + 관심 주제(선택, 칩 + 직접 입력). 나이는 쓰임이 없어 제외. 확장 설치와 북마크 폴더 선택이 뒤에 붙음
4. 요약 생성을 첫 버전으로 당김 (추출은 논문에만 통해서)
5. 읽기 중 기능: 하이라이트 + 메모 + 용어 설명(버튼 하나) + 상호대차. "쉽게 풀어줘", 배경 설명, 자유 질문은 나중
6. 기능 이름은 도서관 용어로 통일 (신간, 임시서가, 전시 서가, 범위주기, 상호대차, 보존 서고)
7. 책 삭제 없음. 대신 보존 서고로 내림
8. 칸 삭제 시 안의 책은 임시서가로 보내거나 사용자가 보낼 칸을 지정
9. 규칙 질문 카드는 선택지마다 영향받는 책 목록을 함께 보여줌
10. 담기의 주 경로는 북마크. 확장 버튼이 보조, iOS 단축어는 폰용
11. 크롬 북마크 가져오기를 첫 버전으로 승격
12. 하이라이트는 원문 페이지와 읽기 뷰어 양쪽에서 가능

**3. 흐름 다섯 개**

흐름 1. 시작하기

1. 크롬 웹스토어나 개발자 모드로 확장 설치
2. 새 탭을 열면 서재 첫 화면. 사서가 인사하고 로그인 요청
3. 이메일을 넣으면 서버가 키를 발급해 확장에 저장 (다음부터는 자동)
4. 이름 입력 (필수). 입력하면 사서가 그 자리에서 한 번 불러줌
5. 관심 주제 입력 (선택, 칩 + 직접 입력) → 사서가 넓은 칸 3~5개 초안 제시 → 고치고 확정
6. 북마크 연결: 자동으로 담을 폴더 지정 (기본은 모든 새 북마크). 기존 북마크는 목록만 읽어두고 담지 않음
7. 빈 서재 화면 + "북마크해보세요" 안내

여기서 새로 나온 것
- 확장 설치와 새 탭 교체 안내
- 서버 발급 키 저장 (로그인)
- 북마크 폴더 선택
- 기존 북마크 목록 보관 (메타만, 수집 없음)
- 빈 서재 화면, 사서 소개 한 줄, 관심 주제 예시 칩

관심 주제를 건너뛰면 칸 없이 시작하고, 담은 책이 임시서가에 모여 3권이 되면 칸을 제안한다
크롬 알림 권한은 저녁 큐레이션을 붙일 때 함께 요청한다
나이는 쓰임이 없어 받지 않는다. 호칭은 이름으로 받는다

흐름 2. 담기

1. 크롬에서 별표를 눌러 북마크 (또는 확장 버튼으로 현재 페이지 담기)
2. 확장이 북마크 생성 신호를 받아 서버로 주소 전송. 새 탭에는 "담는 중" 표시
3. 서버가 원문을 가져옴 → 실패하면 재시도
4. 로그인·유료 기사라 서버가 못 가져오면, 확장이 내가 보고 있는 화면의 본문을 대신 보냄 (A등급 유지)
5. 본문 텍스트 추출, 이미지 저장
6. 메타데이터 추출 (제목·저자·날짜·출처·분량)
7. 주제 분류 3회
8. 갈림: 3회 모두 같은 칸이면 해당 칸에 신간 띠지를 두르고 꽂기, 흔들리면 임시서가로
9. 저장 (본문·메타데이터·분류 결과·신호 로그)
10. 다음에 새 탭을 열면 사서가 결과를 알려주고 그 칸이 반짝임

처음 20권은 사서가 "○○ 칸에 꽂았어요"를 새 탭에서 확인받는다. 북마크로 담을 때는 즉시 뜨는 화면이 없으므로, 확인은 새 탭의 사서 자리에 쌓인다

폰 크롬에서 북마크한 글은 크롬 동기화로 PC에 내려오고, PC 크롬이 켜질 때 담긴다. 즉시 담고 싶으면 iOS 단축어를 쓴다 (다음 버전)

흐름 2-1. 기존 북마크 가져오기

1. 사서가 제안: "예전 북마크가 134개 있네요. 'AI' 폴더의 23개부터 가져와볼까요?"
2. 승인하면 주소만으로 링크 생존 확인
3. 살아 있는 것부터 동시에 두세 개씩 천천히 수집
4. 진행 상황 보고: "23개 중 18개 담았고, 3개는 원본이 사라졌어요"
5. 죽은 링크는 따로 모아 아카이브에서 찾아볼지 물어봄

흐름 3. 훑고 읽기

1. 새 탭을 열면 책장과 사서가 보임. 띠지 두른 책과 빛바랜 책이 눈에 들어옴
2. 안 읽은 책 모아보기로 들어가거나, 칸 하나를 열기
3. 초록 카드 훑기 (한 장씩 넘기기)
4. 깊게 읽기로 들어가거나, 카드만 보고 넘기기
5. 읽기 뷰어: 본문 읽기, 원문 링크 열기, 하이라이트·메모
6. 닫기 → 띠지가 벗겨지고 열람 기록이 남음

여기서 새로 나온 것
- 안 읽은 책 모아보기 (띠지 두른 책만)
- 읽던 위치 저장, "읽는 중" 상태
- 카드만 보고 넘긴 기록
- 본문 수집이 실패한 책: 원문 링크만 + 실패 표시
- 원문 열기

초록 카드 내용
- 검토: 추출로 채우기(논문 초록, 기사 첫 문단) vs 요약 생성을 첫 버전으로 당기기
- 결정: 요약 생성을 첫 버전으로. 추출은 논문에만 통해서 기사 카드가 비게 됨

| 유형 | 카드에 담는 것 | LLM이 하는 일 |
|---|---|---|
| 논문 | 원문 초록 + 한 줄 요지 | 한 줄만 생성 |
| 기사·리포트 | 3줄 요약 | 요약 생성 |

- 담을 때 한 번 만들어 저장
- 요약 문장에서 원문 위치로 이동
- 다시 생성, 직접 수정 버튼이 요약 품질의 신호
- 자동 환각 검사는 다음 버전

흐름 4. 메모하기

경로 둘 다 같은 기록을 쓴다.

원문 페이지에서
1. 웹을 보다가 문장을 선택
2. 선택 근처에 작은 메뉴: 하이라이트 / 메모 / 용어 설명 / 서재에서 읽기
3. 담기지 않은 페이지면 먼저 담고 하이라이트를 붙임
4. 이미 서재에 있는 페이지면 기존 하이라이트를 페이지 위에 복원해서 보여줌

읽기 뷰어에서
1. 본문에서 문장을 선택
2. 같은 메뉴
3. 하이라이트 → 포스트잇이 본문 위치에 맞춰 붙음
4. 메모 → 입력 → 하이라이트에 메모 표시
5. 용어 설명 → 뜻풀이 두세 줄 + "서재 밖 지식" 표시 → 그대로 두기 / 고치기 / 지우기
6. 용어 설명 카드의 "더 찾아보기" → 상호대차
7. 책을 덮은 뒤: 그 책의 메모 모아보기

여기서 새로 나온 것
- 원문 페이지 위 도구 모음과 하이라이트 복원
- 위치 저장 방식: 선택한 문장 + 앞뒤 30자 + 문단 번호
- 저장본에서도 같은 문장을 찾아 위치를 계산해 양쪽에 반영
- "위치를 찾지 못했어요" 상태
- 메모 종류 구분 (하이라이트만 / 메모 붙은 하이라이트 / 용어 메모)
- 메모 수정·삭제, 메모 모아보기, 책 전체 메모

제약
- PDF는 크롬 기본 뷰어 위에서는 어려움. 우리 뷰어로 열면 됨 (다음 버전)
- 인터넷이 끊기면 확장 저장소에 넣어두고 연결되면 올림 (다음 버전)
- 폰(PWA)에서는 저장본에서만 가능

용어 설명 범위
- 첫 버전: 버튼 하나로 뜻풀이만. 사서가 자기 지식으로 쓰고 "서재 밖 지식" 표시
- 같은 용어를 다시 선택하면 저장해둔 설명을 먼저 보여줌
- 다음 버전: 임베딩을 붙여 내 서재 안에 근거가 있으면 그 책으로 연결
- 화면이 빽빽해지지 않게: 본문에는 밑줄만, 누르면 작은 카드로

용어 설명과 상호대차의 구분

| | 용어 설명 | 상호대차 |
|---|---|---|
| 언제 | 읽다가 막혔을 때 | 읽다가 더 알고 싶어졌을 때 |
| 하는 일 | 짧은 뜻풀이를 책 안에 메모로 남김 | 서재 밖에서 찾아와 새 책으로 담음 |
| 끝난 뒤 | 읽던 자리로 돌아감 | 서재에 책이 한 권 늘어남 |
| 도서관으로 치면 | 사전 찾기 | 서가에 없는 자료를 다른 도서관에서 받아오기 |

"서재 밖 지식"은 기능이 아니라 용어 설명에 붙는 출처 표시다. 표시를 누르면 밖에서 근거를 찾아 출처 2~3개를 보여주고, 출처마다 "이 글 담기" 버튼이 붙는다

흐름 5. 고치기

1. 책을 끌어서 다른 칸으로 옮김 (또는 책 상세에서 칸 옮기기)
2. 옮긴 기록만 남고 사서는 조용
3. 같은 방향 이동이 3번째가 되면, 다음에 새 탭을 열 때 사서 자리에 질문 카드가 놓임
4. 질문 카드: 앞으로도 이렇게 / 이번 책들만 / 새 칸 만들기 (선택지마다 영향받는 책 목록을 함께 표시)
5. "앞으로도"를 고르면 범위주기 전후와 영향 미리보기
6. 승인 → 반영, 버전 저장, 되돌리기
7. 칸을 직접 고칠 때는 바로 반영되고 그 자리에서 사서가 질문. "직접 관리할게요"를 고르면 이름표가 손글씨로 바뀜

여기서 새로 나온 것
- 임시서가에서 직접 꽂기
- 범위주기 직접 편집
- 되돌리기 (직후에는 배너, 그 뒤에는 버전 목록)
- 질문 카드가 놓이는 자리 (새 탭의 사서 자리, 하루 2개까지)

칸 삭제: 지울 때 "이 책들을 어디로 보낼까요?"를 묻고, 임시서가 또는 사용자가 지정한 칸으로 보냄

책 삭제 없음: 대신 보존 서고로 내림. 책장에서는 안 보이고 검색하면 나옴. 추천·큐레이션·전시 후보에서 빠지고 칸 두께에도 안 세짐. 같은 글을 두 번 담으면 한 권으로 합치고 메모는 모아둠

북마크 쪽 변화: 북마크를 지우면 보존 서고로 내림. 북마크 폴더를 옮긴 것은 첫 버전에서 무시하고, 다음 버전에서 "칸도 옮길까요?"로 받는다

참조 카드는 규칙이 바뀌거나 책이 옮겨질 때 다시 계산해서 따라간다

**4. "앞으로도" 규칙 반영 로직**

데이터

| 저장하는 것 | 내용 |
|---|---|
| 이동 기록 | 책 id, 이전 칸, 새 칸, 시각, 그때의 분류 근거 |
| 범위주기 | 칸마다 `{포함: [문장들], 제외: [{조건, 보낼 칸}]}`. 분류 프롬프트에 그대로 들어감 |
| 범위주기 버전 | 버전 번호, 변경 전후, 근거가 된 이동 기록 id, 적용 시각 |
| 재질문 금지 목록 | (이전 칸, 새 칸, 특징) 조합. "이번 책들만"을 고른 것이 들어감 |

1. 질문이 뜨는 조건 (코드): 최근 30일 안에 같은 (이전 칸 → 새 칸) 이동이 3건 쌓이고, 그 조합이 재질문 금지 목록에 없을 때. 조건이 맞으면 질문 카드를 대기열에 넣고 새 탭에서 하루 2개까지 표시

2. 규칙 후보 만들기 (LLM, 형식 고정)
- 입력: 옮긴 책 3권의 제목·요약·원래 분류 근거 + 두 칸의 현재 범위주기
- 출력 형식: `{ "특징": "에이전트를 평가하는 글", "이전 칸 제외 추가": "에이전트 평가를 다루면 → 에이전트", "새 칸 포함 추가": "에이전트의 성능·품질 평가" }`
- 코드 확인: 형식이 맞는지, 건드리는 칸이 그 두 개뿐인지, 기존 문장과 겹치지 않는지

3. 영향 미리보기 (코드 + LLM, 비용 상한)
- 후보 고르기: 이전 칸의 책 중 그 특징에 가까운 순으로 최대 20권
- 새 범위주기로 다시 분류 (LLM 호출 20회 상한)
- 칸이 바뀌는 책만 목록으로 표시
- 첫 20권 정답 세트도 다시 분류해 함께 표시. 정답 유지율이 떨어지면 경고 (회귀 확인)

4. 승인 후 (코드): 범위주기 새 버전 저장 → 바뀐 책 실제 이동 → 참조 카드 재계산 → 되돌리기 배너

5. 되돌리기: 버전을 되돌리면 범위주기가 이전 버전으로 돌아가고, 그때 함께 옮긴 책들도 원래 칸으로

6. 다른 선택지
- 이번 책들만: 그 책들에 "이 자리 고정" 표시, (이전 칸, 새 칸, 특징)을 재질문 금지 목록에 추가
- 새 칸 만들기: 칸을 만들고 범위주기 초안을 받은 뒤 같은 미리보기 단계를 거침

비용: 질문 한 번에 LLM 호출 최대 41회(규칙 후보 1 + 미리보기 20 + 정답 세트 20). 하루 질문 상한 2개라 하루 82회가 최대

**5. 기능 이름 규칙**

도서관 용어로 통일한다. 신간(띠지), 임시서가, 전시 서가, 진열대, 범위주기, 상호대차, 보존 서고, 참조 카드. 새 기능이 생기면 "도서관에서 이걸 뭐라고 부르지?"가 이름 짓는 기준이 된다

흐름을 다 그린 뒤 따로 모을 것 (문구·캐릭터)
- 사서 캐릭터: 집사 고양이. 말투, 호칭, 파츠 조합
- 화면 문구: 인사, 빈 서재, "담는 중", 확인 카드, 질문 문구
- 실패 문구: 수집 실패, 원본 사라짐, 위치를 찾지 못함

**6. 플랫폼과 저장 구조 (확정)**

형태: 크롬 확장. 새 탭이 곧 서재
- 새 탭은 하루에 수십 번 열려서 "다시 열 이유"를 따로 만들지 않아도 된다
- 확장이라 크롬 북마크를 읽고 쓸 수 있다
- 원문 페이지 위에서 하이라이트할 수 있어 로그인·유료 기사에서도 해석이 쌓인다
- 넓은 화면이라 책등이 커지고 제목이 읽힌다

화면 셋: 새 탭(서재), 읽기 뷰어, 3D 서재. 여기에 원문 페이지 위 도구 모음

폰: 아이폰 크롬은 확장을 지원하지 않는다. 폰에서 직접 담는 것은 iOS 단축어(다음 버전), 폰 크롬 북마크는 PC를 켤 때 동기화로 들어온다. 사파리 북마크는 들어오지 않는다

저장: 서버에 두고 확장은 화면 역할
- 수집이 서버에서 돌아야 안정적이다
- 검색도 서버에서 하면 본문 전체 검색을 처음부터 넣을 수 있다
- 확장 저장소는 임시 보관(오프라인 메모, 발급 키)에만 쓴다

서버 구성: 관리형 서비스 조합

| 부분 | 선택 |
|---|---|
| 화면 | Vite + React, 확장에 번들 |
| API·수집 워커 | Python + FastAPI, Railway |
| 본문 추출 | trafilatura |
| 렌더링 | Playwright (필요할 때만) |
| PDF | pdfplumber |
| DB | 관리형 Postgres (Supabase 등) |
| 파일 | Cloudflare R2 |
| 작업 큐 | procrastinate (파이썬, Postgres만으로 동작) |
| 로그인 | 서버 발급 키를 확장에 저장 |
| 3D·폰트 | 확장은 외부 코드를 불러올 수 없어 파일로 포함 |

지킬 것: 원문 저장소는 비공개. 공개 저장소·공개 버킷에 올리지 않음

원문 저장소와 서비스 저장소는 코드와 데이터 모델에서 분리해둔다. 상업화 시점에 원문 저장소만 사용자 쪽으로 옮길 수 있게

**8. 옵시디언 공존**

저장 형식을 마크다운으로 맞춘다. 칸이 폴더가 되고, 책 한 권이 파일 하나가 된다

```
서재/
  LLM 평가/
    Who Validates the Validators.md
  에이전트/
  _임시서가/
  _보존서고/
  _원문/
```

파일 안쪽: frontmatter(title, authors, source, arxiv, published, captured, type, shelf, archive) + 요약 / 내 메모 / 하이라이트(인용 + 본문 위치) / 용어

| 방식 | 시점 |
|---|---|
| 내보내기 (zip으로 받아 볼트에 넣기) | 첫 버전 |
| 깃허브 비공개 레포 동기화 | 다음 버전. Phase 앱 구상과 같은 길 |
| 폴더 동기화 (드롭박스·아이클라우드) | 다음 버전 |

양방향은 나중으로. 처음에는 서재앱 → 볼트 한 방향만

**9. 첫 버전 완료 기준**

1. 북마크하면 원문이 저장되고 칸에 꽂힌다
2. 20권을 담아 첫 정답 세트가 만들어진다
3. 새 탭에서 책장과 사서가 보이고, 안 읽은 책을 훑어 읽을 수 있다
4. 원문 페이지와 읽기 뷰어 양쪽에서 하이라이트·메모·용어 설명이 남고, 상호대차로 새 책이 들어온다
5. 책을 세 번 옮기면 사서가 규칙을 묻고, 승인하면 범위주기가 바뀌고 되돌릴 수 있다

5번까지 돌아가면 "사용 신호로 분류가 나아지는 앱"이라는 이야기가 완성된다

범위를 잠근 뒤 바꾸는 규칙: 첫 버전 기간에 새 아이디어가 나오면 목록에 적어두고 다음 버전 후보로 둔다. 첫 버전에 넣으려면 대신 뺄 것을 하나 정한다
