**서재앱 04 화면**

이 문서가 답하는 질문: 기능이 어느 화면에서 어떻게 보이고, 무엇을 누르면 어디로 가나
현재 기준 문서. 결정이 바뀌면 이 자리에서 고친다. 바뀐 이력은 `서재앱_00_허브.md` 결정 로그에 남긴다.
화면 번호는 이 문서에만 둔다. 다른 문서는 번호로 가리킨다.
버전은 03을 따른다. 아래 화면 목록의 버전 표시는 03 기준으로 옮긴 것이고, 어긋나면 03이 우선한다.
흐름(순서와 갈림길)은 03 9절 흐름도가 원본이다. 이 문서는 그 흐름이 지나가는 화면을 정의한다.
색·글꼴·간격은 디자인 단계에서 정한다. 읽기 등급(A·B·C)의 정의는 05.
말의 주체: "나"는 서재앱 사용자(다혜), "사서"는 앱 안의 LLM.
용어: "들어오는 글"은 칸마다 이 칸에 들어오는 것과 다른 칸으로 가는 것을 적은 기준이다. 화면에는 "이 칸에 들어오는 글"로 보인다. 도서관 용어로는 범위주기 (02 1절).

---

**1. 화면의 전제**

- 크롬 확장. 새 탭이 곧 서재다
- 확장 안 화면: 새 탭(서재), 읽기 뷰어, 그 밖의 목록·설정 화면. 모두 확장에 번들된 페이지
- 겹침: 새 탭이나 뷰어 위에 카드로 뜨는 것 (초록 카드, 질문 카드, 확인 카드 등)
- 웹페이지 위: 원문 페이지에 확장이 얹는 것. MVP는 페이지 위 알림(S30) 하나, 다음 버전에 선택 도구 모음(S20)
- 넓은 화면 기준이다. 책등이 커지고 한글 제목이 읽힌다. 한 칸에 8~10권이 보이고 나머지는 옆으로 민다 (02 8절)
- 새 탭은 가볍게 떠야 한다. 하루에 수십 번 열린다
- 그래픽 예산은 사서에 몰고, 책장과 목록은 단순한 도형과 글자로. 책장과 종이는 차분하게, 사서와 이펙트만 카툰풍
- 서버에 연결하지 못하면 사본을 보여주지 않고 연결 실패를 분명하게 안내한다 (03 F1)

**3. 공통 요소**

여러 화면에서 같은 모양으로 쓰는 것들. 한 번 만들어 모든 흐름에서 쓴다.

| 요소 | 모양 | 쓰는 곳 |
|---|---|---|
| 확인 카드 | 무엇이 바뀌고 무엇이 남는지 한두 줄 + 확정 / 취소 | 로그아웃(A3), 계정 삭제(A4), 칸 삭제(C5), 원문 비우기(C9), 서재 폴더 끄기(E4), 담지 않는 사이트 추가 시 기존 책 처리(E3) |
| 미리보기 카드 | 바뀌기 전후, 옮겨질 책 목록, 정답지 회귀("20권 중 19권 그대로예요"), 유지율이 떨어지면 경고 + 확정 / 취소 | 규칙 질문(C2-2), 칸 만들기(C3), 나누기·합치기(C4), 들어오는 글 편집(C6), 되돌리기(C7) |
| 되돌리기 배너 | 화면 아래 "바뀌었어요 · 되돌리기". 몇 초 뒤 사라지고, 그 뒤에는 S11 버전 목록에서 | 규칙 승인, 칸 만들기·나누기·합치기·삭제, 들어오는 글 편집 |
| 사서 말풍선 | 사서 옆 한 줄. 누르면 S31로 | 보고, 질문, 인사 |
| 상태 띠 | 화면 위쪽 가는 띠 + 행동 버튼 하나 | 일부만 담김, 읽기 품질 낮음, 근거를 찾지 못했어요, 연결 실패 |
| 칸 고르기 | 지금 칸 이름을 누르면 칸 목록이 펼쳐짐(기존 칸, 임시서가, + 새 칸). 고르면 "○○ 칸으로 옮겼어요 · 되돌리기". + 새 칸은 칸 만들기(C3)와 같은 미리보기를 거침 | 초록 카드(S06), 뷰어 더보기(S07), 사서 보고(S31), 정답지 확인 카드(S17) |
| 기다리는 동안 사서의 말 | 사서의 한 줄 + 숫자 진행률. 말은 재미있게 쓰되 실제 단계와 맞춤 (4절 표) | 담는 중, 가져오는 중, 다시 담는 중, 내보내는 중 |
| 인라인 질문 | 방금 한 동작 옆에 작게. 상한 밖 | 정답지 책 옮김("처음 확인하신 칸과 다른데 옮길까요", C2-1), 사서 관리 칸 이름 바꿈·편집 뒤 "이번만 / 직접 관리"(C3, C6) |

도서관 느낌을 지키는 디자인 메모 (디자인 단계의 기준)

화면 흐름은 도서관에서 책을 고르는 순서와 같다: 서가 앞에서 책등을 훑고(새 탭, 칸 화면) → 한 권 뽑아 앞날개를 보고(초록 카드) → 자리에 앉아 읽고(뷰어) → 제자리에 꽂는다(닫기). 느낌이 줄어드는 위험은 흐름보다 모양에서 온다.
- 칸 화면은 카드 목록이 아니라 책등이 꽂힌 책장으로 보여준다
- 책을 누르면 책이 서가에서 살짝 빠져나오면서 카드가 뜬다. "뽑아 드는" 느낌
- 초록 카드는 도서관 목록 카드나 책의 앞날개처럼 생기게 한다 (줄 그어진 종이, 서지 정보가 위에)
- 넘기기는 옆 책을 꺼내는 것, 닫기는 제자리에 꽂히는 모션. 옮긴 책은 새 칸에 반짝이며 꽂히고, 원래 자리에 이동 흔적이 남는다
- 칸 고르기의 동작은 아티팩트 "칸 고르기 동작 목업"에서 확인할 수 있다. 이 목업은 누르면 어떻게 되는지만 보여주는 동작 확인용이다. 색, 글꼴, 책 모양, 사서 그림은 자리를 채운 임시 모양이라 디자인 기준으로 삼지 않는다. 실제 디자인은 디자인 단계에서 시안을 여러 개 나란히 놓고 따로 정한다

**4. S02 새 탭 (서재)과 S31 사서 자리**

영역
- 책장: 칸들이 한눈에. 띠지·빛바램·책등 색·두께가 보인다. 새로 꽂힌 책이 있는 칸은 은은하게 빛나고, 여러 권이면 칸마다 개수
- 사서와 사서 자리: 사서가 상태에 따라 무언가 하고 있다(MVP는 정지 그림 + 말풍선, 애니메이션은 다음). 쌓인 항목 수가 보이고, 누르면 S31이 펼쳐진다
- 검색 입구
- 이동: 임시서가, 안 읽은 책, 칸 만들기, 설정
- 칸 순서: 칸을 끌어서 바꿈. 처음 순서는 사서가 책이 많은 칸부터 정하고, 새 칸은 맨 뒤에 붙음 (C10)

상태

| 상태 | 보여주는 것 | 흐름 |
|---|---|---|
| 평소 | 책장, 사서, 검색 | |
| 빈 서재 | 칸은 있고 책은 없음 + "북마크해보세요". 가져오기를 건너뛴 경우 | A1 |
| 담는 중 | 사서가 책을 안고 걷는 중, 기다리는 동안 사서의 말 | B1-2 |
| 가져오는 중 | 진행률("88권 중 34권"), 사서의 말, 책장에 책이 하나씩 꽂힘. 온보딩에서 가져오기를 골랐다면 칸이 생기기 전이라 책이 임시서가에 쌓이고, 끝나면 사서가 칸 초안을 제안 | B2 |
| 로그인 필요 | 사서가 "다시 로그인해 주세요" + 로그인 버튼. 서재 내용은 보이지 않음 | A2, A3 |
| 연결 실패 | "서재에 연결하지 못했어요". 책장과 책은 보이지 않음. 장애 중 북마크는 확장이 들고 있다가 연결되면 보냄 | F1 |

규칙
- 가볍게 떠야 한다. 무거운 것(3D, 큰 이미지)은 새 탭에 올리지 않는다
- 칸 순서는 저절로 바뀌지 않는다 (자리 안정성, 02 9절)
- 사서의 보고를 누르면 그 자리(칸)로 이동하며 해당 책이 반짝인다
- 사서를 누르면 사서가 말을 걸며 메뉴가 펼쳐진다 (사서 자리 목록, 사서 데스크, 검색, 임시서가, 설정)

S31 사서 자리에 쌓이는 항목

| 항목 | 종류 | 하루 2개 상한 | 기한 | 흐름 |
|---|---|---|---|---|
| 규칙 질문 | 질문 → S16 | 안 | 14일 | C2-1, C2-2 |
| 새 칸 제안, 가까운 칸으로 옮기기 제안 | 질문 | 안 | 14일 | C8 |
| 기존 북마크 가져오기 제안 | 질문 → S14 | 안 | 14일 | A1, E2 |
| 놓친 북마크 N개를 담을까요 | 질문 | 안 | 14일 | B3 |
| 정답지 확인, 정답지 보강 | 확인 → S17 | 밖 | 7일 | C1, C3 |
| 담을지 물어볼 로그인 페이지 N개 | 질문 | 밖 | 7일 | B1-2 |
| 로그인이 풀린 동안 북마크한 N개를 담을까요 | 질문 | 밖 | 로그인하면 바로 | A2 |
| 없는 동안 북마크한 N개를 담을까요 | 질문 | 밖 | 재설치하면 바로 | A5 |
| 수집 결과 보고 ("어제 담은 세 권 정리해뒀어요") | 보고 | 밖 | 읽으면 사라짐 | B1-3 |
| 실패 보고 ("두 건은 못 가져왔어요") → S13 | 보고 | 밖 | 읽으면 사라짐 | B4 |
| 가져오기 진행 보고 | 보고 | 밖 | 끝나면 결과로 바뀜 | B2 |
| 북마크를 지우셔서 보존 서고로 옮겼어요 | 보고 | 밖 | 읽으면 사라짐 | B5 |
| 내보내기가 끝났어요 → S33 | 보고 | 밖 | 받으면 사라짐 | E5 |

- 기한이 지나면 항목만 사라지고 기록은 남는다. 기한별 처리는 03 F2
- 질문이 여러 개면 한 번에 1~2개씩 보여준다. 읽는 중에는 뜨지 않는다
- 수집 결과 보고에는 책마다 꽂힌 칸이 붙고, 칸 이름을 눌러 바로 옮길 수 있다 (칸 고르기)

기다리는 동안 사서의 말 (초안, 문구 정리 때 다듬음)

| 실제 단계 | 사서의 말 |
|---|---|
| 링크 확인 | 책이 아직 있는지 확인하는 중 |
| 원문 수집 | 책을 받아오는 중 |
| 본문 추출 | 먼지 털어내는 중 |
| 분류 3회 | 어느 칸이 어울릴지 고민하는 중 |
| 요약 | 초록 쓰는 중 |
| 칸 초안 (가져오기 뒤) | 책들을 보고 칸을 나눠보는 중 |
| 정답지 준비 | 확인받을 책 고르는 중 |
| 내보내기 | 서재를 상자에 담는 중 |

- 말은 재미있게 쓰되 실제로 하고 있는 단계와 맞아야 한다. 아무 말이나 돌리면 "진짜 뭘 하고 있나" 싶어진다
- 숫자 진행률("88권 중 34권")을 같이 보여준다

결정 필요
- 서재 전체 보기의 모양: 세로로 이어진 서가 / 칸 카드 넘기기 / 전체 보기 없이 칸부터. 넓은 화면이라 칸이 한눈에 들어올 가능성이 크다
- 새 탭 레이아웃(책장·사서·검색의 배치)은 새 탭 설계 단계에서 그린다
- 할 일 영역은 후보(03 2-6)라 지금은 자리를 두지 않는다

**5. S07 읽기 뷰어**

목적: 저장한 본문을 읽는다. 다음 버전에서 하이라이트·메모·용어 설명이 여기 붙는다
진입: 초록 카드의 "읽기", 검색 결과, (다음 버전) 칸 이어 읽기, 메모 모아보기, 원문 페이지의 "서재에서 읽기"
나갈 때: 들어온 화면으로. 그 책이 꽂힌 자리가 보이는 상태로

영역 구성 (위에서 아래로)

| 영역 | 담기는 것 |
|---|---|
| 상단 바 | 뒤로, 책 제목(한 줄 줄임), 읽기 모드 토글(텍스트/원문), 더보기 |
| 상태 띠 | 필요할 때만: 일부만 담김, 읽기 품질 낮음, 근거를 찾지 못했어요 |
| 판 기록 | 판이 바뀐 책만: 발행일 옆에 "v2 · 이전 판 1개". 누르면 이전 판의 ID(또는 캡처 날짜)·발행일·담은 날짜와 그때의 요약이 접힌 목록으로. arXiv는 이전 판 주소를 열 수 있음. 되돌리기 버튼은 없음 (05 4-4) |
| 진행 막대 | 읽은 위치를 얇은 선으로 (책갈피 리본) |
| 요약 블록 | 논문은 원문 초록 + 한 줄 요지, 기사는 3줄 요약. 접고 펼 수 있음. 다시 생성, 직접 수정, 이전 버전으로. 판이 바뀐 책은 이전 판의 요약도 이전 버전 목록에 들어감 |
| 본문 | 문단, 소제목, 인용, 이미지와 캡션, 그림 자리표시 |
| 하단 바 | 원문 열기. (다음 버전) 메모 n개 보기 |

요소별 동작

| 요소 | 누르면 | 기록되는 신호 | 버전 |
|---|---|---|---|
| 뒤로 | 들어온 화면으로. 읽은 기준을 넘었으면 띠지가 벗겨진 상태 | 열람 기록 | MVP |
| 읽기 모드 토글 | 텍스트 ↔ 원문 | 원문 모드로 넘어간 횟수 | MVP |
| 더보기 | 다시 담기(원문을 새 탭으로 열어 다시 뜸) / 칸 옮기기(칸 고르기) / 보존 서고로 내리기 / 사서 기록 보기 / (그다음) 공유 | 다시 담기 누름, 칸 이동 | MVP |
| 요약 접기 | 요약을 접고 본문부터 | 요약을 접는 빈도 | MVP |
| 요약 문장 | 그 문장의 원문 위치로 이동. 못 찾으면 "원문에서 근거를 찾지 못했어요" 띠와 다시 생성 제안 | 근거 확인 횟수, 근거 못 찾음(환각 의심) | MVP |
| 요약 다시 생성 | 새 요약 생성, 마음에 안 들면 이전 버전으로 | 요약 재생성 | MVP |
| 요약 직접 수정 | 편집 가능, 저장하면 "내가 고친 요약" 표시. 다시 생성해도 버전으로 남음 | 요약 수정(고치기 전후) | MVP |
| 원문 열기 | 원문 링크를 새 탭으로 | 원문 이탈 | MVP |
| 문장 선택 | 작은 메뉴: 하이라이트 / 메모 / 용어 설명 | 선택 위치 | 다음 2순위 |
| 하이라이트 | 밑줄 표시, 포스트잇 한 개 추가 | 하이라이트 생성 | 다음 2순위 |
| 메모 | 입력창, 저장하면 하이라이트에 메모 표시 | 메모 생성 | 다음 2순위 |
| 용어 설명 | 용어 설명 카드가 아래에서 올라옴 | 용어 설명 요청 | 다음 2순위 |
| 그림 | 그림 설명 카드. 캡션이 있으면 캡션, 없으면 사서 설명 | 그림 설명 요청 | 다음 2순위 |
| 메모 n개 보기 | 메모 모아보기 화면으로 | | 다음 2순위 |

(요소별 버전 표시는 03 기준. 어긋나면 03이 우선)

상태별 화면

| 상태 | 보여주는 것 |
|---|---|
| 본문 준비 중 | 제목과 메타데이터는 보이고 본문 자리에 뼈대 표시 |
| 이어 읽기 | 전에 읽던 책이면 상단에 "이어서 읽기 / 처음부터"를 한 번 |
| A등급 | 기본 화면 |
| 일부만 담김 | 상태 띠 "일부만 담겼을 수 있어요"와 다시 담기 안내 (원문 페이지에서 더보기를 펼친 뒤 S30의 "여기서 다시 담기") |
| B등급 | 상태 띠 "읽기 품질이 낮아요"와 다시 담기 버튼. 원문 모드 권유 |
| C등급 | 본문 자리에 안내와 원문 링크. 요약 없음, 메타데이터는 보임. (다음 버전) 하이라이트는 막고 책 전체 메모만 |

보여줄 데이터: 제목, 저자, 매체·출처, 발행일, 담은 날짜, 유형, 분량, 읽은 위치, 요약, 요약 버전, 본문, 이미지와 캡션, 읽기 등급, 원본 링크, 아카이브 주소, 판 기록. (다음 버전) 하이라이트 목록, 메모 목록, 용어 설명 목록

규칙
- 읽은 것으로 치는 기준: 본문에서 20% 이상 내려가거나 30초 이상 머물면, 닫을 때 띠지가 벗겨진다. 실수로 열었다 닫은 것은 읽은 것이 아니다. 읽던 위치는 어느 쪽이든 저장한다
- 읽는 중에는 사서가 말을 걸지 않는다. 질문은 새 탭에 쌓인다
- 원문 모드는 표·수식 확인용이다. 원문 페이지에서 직접 하이라이트하는 것(S20)과는 다르다
- (다음 버전) 하이라이트는 저장한 본문 텍스트 기준이라 다시 담기를 하면 위치가 어긋날 수 있다. 어긋난 하이라이트는 지우지 않고 "위치를 찾지 못했어요"로 남긴다
- (다음 버전) 용어 설명과 그림 설명은 눌렀을 때만 만들고, 한 번 만든 것은 저장해 다시 쓴다

**7. S20 원문 위 도구 모음 (다음 버전 2순위)**

목적: 웹을 보다가 그 자리에서 하이라이트·메모·용어 설명을 남긴다

- 문장을 선택하면 선택 영역 근처에 작은 메뉴가 뜬다: 하이라이트 / 메모 / 용어 설명 / 서재에서 읽기
- 이 페이지가 이미 서재에 있으면 기존 하이라이트를 페이지 위에 복원해 보여준다
- 담기지 않은 페이지에서 하이라이트하면 먼저 담고 하이라이트를 붙인다
- 확장 아이콘(S26)에 이 페이지의 상태를 표시한다 (서재에 있음 / 없음 / 수집 중)

위치를 기억하는 방법
- 선택한 문장 그대로, 앞뒤 30자, 몇 번째 문단인지를 함께 저장한다
- 다시 열 때 문장을 찾아 표시한다. 구조가 바뀌어도 문장이 그대로면 찾아진다
- 같은 문장을 저장본에서도 찾아 위치를 계산해둔다. 그래서 원문에서 그은 하이라이트가 뷰어·메모 모아보기·책등 포스트잇에 모두 반영된다
- 찾지 못하면 지우지 않고 "위치를 찾지 못했어요"로 남긴다
- 원문이 사라져도 저장본 위치로 옮겨져 있어 하이라이트는 남는다

제약
- PDF는 크롬 기본 뷰어 위에서는 어렵다. 우리 뷰어로 열어야 한다
- 인터넷이 끊기면 확장 저장소에 넣어두고 연결되면 올린다 (오프라인 메모와 함께)
- 폰(PWA)에서는 원문 위 하이라이트가 안 되고 저장본에서만 가능하다

**8. S01 온보딩과 S12 설정**

온보딩 순서와 필수·선택 (흐름 A1, 재설치는 A5)

| 단계 | 필수 | 건너뛰면 |
|---|---|---|
| 확장 설치 | 필수 | |
| 구글 계정 로그인 (크롬에 로그인한 계정으로 한 번 승인) | 필수 | 서버 저장이라 건너뛸 수 없음. 서버에 이 계정의 서재가 있으면 "다시 오셨네요"로 (A5) |
| 수집 범위 안내 | 필수 (읽고 넘기기) | 모으는 것: 북마크한 페이지의 본문과 이미지 주소, 제목·저자·날짜. 모으지 않는 것: 북마크하지 않은 페이지, 방문 기록, 담지 않는 사이트. 로그인해야 보이는 페이지는 담기 전에 물어봄. 크롬 북마크 폴더는 읽기만 함 |
| 사이트 읽기 권한 요청 | 선택 | 왜 필요한지(북마크한 페이지의 본문을 그 자리에서 뜨기 위해) 설명하고 크롬 권한 창을 띄움. 거절하면 "서버가 대신 읽어요. 로그인해야 보이는 페이지는 제목·링크만 담겨요"를 알리고 다음으로. 설정의 수집 묶음과 다시 담기에서 켤 수 있음 (A1, B4). 재설치하면 다시 물음 (A5) |
| 담지 않는 사이트 기본값 확인 | 선택 (그대로 넘겨도 됨) | 메일, 은행·결제, 문서 도구 등. 설정에서 언제든 고침 |
| 이름 | 필수 | 비우면 다음으로 못 넘어감("이름을 알려주세요" 안내). 입력하면 사서가 한 번 불러줌. 설정에서 변경 가능 |
| 북마크 폴더 선택 | 선택 | 기본은 모든 새 북마크를 담음 |
| 기존 북마크 가져오기 | 선택 | 고르면 S14로. 칸은 수집이 끝난 뒤 사서가 들어온 책을 보고 제안하고, 확정하면 정답지로 이어짐 |
| 관심 주제 (칩 + 직접 입력) | 가져오기를 건너뛴 경우만, 선택 | 칸 없이 시작. 임시서가에 3권 모이면 칸 제안 |
| 칸 초안 확인 | 관심 주제를 적었으면 필수 | 칸 이름만 확인. 들어오는 글은 정답지 확인 카드에서 한 줄로 |

- 중간에 창을 닫으면 다음 새 탭에서 멈춘 단계부터 이어간다
- 크롬 알림 권한은 저녁 큐레이션을 붙일 때 함께 요청한다

S32 사이트 목록
- 두 목록을 나란히: 담지 않는 사이트 / 묻지 않고 담는 사이트. 둘 다 사용자만 정한다
- 담지 않는 사이트에 추가: 그 사이트 책이 이미 있으면 확인 카드(그대로 두기 / 보존 서고로 / 보존 서고로 + 원문 비우기)
- 담지 않는 사이트에서 빼기: 앞으로의 북마크부터 담김
- 묻지 않고 담는 사이트에서 빼기: 다음부터 다시 물어봄
- 목록마다 어디서 들어왔는지 표시: 앱 기본값 / 내가 추가 / 로그인 알림에서

S33 내보내기
- 범위: 전체 / 칸 골라서. 원문 포함(기본 포함)
- 서버가 마크다운 zip을 만든다. 칸은 폴더, 책은 파일 하나. 창을 닫아도 계속되고, 다 되면 사서가 알려준다
- 실패하면 사유와 다시 만들기
- 파일 구성 세부 규칙은 05

**9. S34 사서 데스크와 남은 결정**

S34 사서 데스크 (흐름 D4)
- 서재 기록을 따로 한 페이지로 뺐다. 설정 안에만 두면 잘 안 들어가게 되므로, 들어가는 길은 두 개: 사서를 누르면 뜨는 메뉴, 설정
- 포지셔닝상 "사서가 나를 얼마나 알게 됐는지 보는 핵심 자리"다. 도서관의 안내 데스크처럼, 사서가 한 일을 보고받는 곳

| 영역 | 담기는 것 |
|---|---|
| 사서 일지 | 칸 이동 비율, 정답지 유지율. 숫자만 나열하면 대시보드가 되어 서재 분위기와 따로 놀기 때문에, 숫자 옆에 "지난달보다 칸 이동이 줄었어요" 같은 한 줄 |
| 칸별 기준 기록 | 칸마다 들어오는 글이 언제, 왜 바뀌었는지. 누르면 S11 버전 목록 |
| 이 책이 걸어온 길 | 책마다 담긴 경로, 분류 3회 결과, 맞은 들어오는 글 문장, 내가 옮긴 기록, 근거가 된 규칙 버전. 초록 카드와 뷰어의 "사서 기록 보기"로도 열림 |

- 기록의 사실(날짜, 경로, 분류 결과, 버전)은 로그에서 코드로 그대로 가져오고, LLM은 문장 다듬기만 한다. 사서가 "왜 그랬는지" 이야기를 지어내지 않게
- 무엇을 어떤 숫자로 보여줄지 세부는 02 14절 지표에서 고른다

남은 결정
- 서재 전체 보기의 모양 (4절)

여기서 보이는 것
- 초록 카드가 길목이다. 새 탭, 칸, 안 읽은 책, 임시서가, 보존 서고에서 둘러보다 책을 누르면 모두 초록 카드로 들어온다. 찾아서 들어온 경우(검색, 칸 이어 읽기, 메모 모아보기, 원문의 "서재에서 읽기")만 바로 뷰어로 간다
- 읽기 뷰어가 가장 복잡하다. 다음 버전에서 선택 메뉴, 용어 설명, 그림 설명, 상호대차, 메모가 모두 여기 걸린다
- 사서 자리가 새 탭에 하나뿐이다. 질문, 정답지 확인, 보고가 모두 S31로 모인다. 하루 2개 상한도 여기서 지켜진다
- 담는 입구: MVP는 북마크와 가져오기. 다음 버전에 확장 아이콘, 원문 위 도구 모음, 상호대차, 신착 서가가 더해진다. 모두 같은 수집 흐름으로 들어간다
- 규칙을 바꾸는 모든 동작(규칙 질문, 칸 만들기·나누기·합치기, 들어오는 글 편집, 되돌리기)은 같은 미리보기 카드를 지난다
